# 验收功能入口

适用版本：v3；score 通用，arm/release/hook 仍是维护项目内的可选实验。按技能完成分流后，以技能真实目录定位脚本，以当前验收目录绝对路径定位原要求与 [输入协议](rubric.md)，准备真实契约和评审工件；表中参数表示文件或值，不能把它们当成已有输入。当前工具不包含业务执行器，不会修复工件里的业务问题。

| 功能 | 真实入口 | 前置条件与应观察结果 | 产生的状态或文件 |
|---|---|---|---|
| 汇总验收 | `work_eval.py score 契约文件 评审文件` | v3输入、真实工件及评审哈希完整；退出0为pass，1为fail/partial/provisional，2为输入或读取错误。读取具体缺口及动作，不用总分判完成 | 契约目录的 `work-eval-score.json` 和 `.md`，报告绑定 contract_path；同目录忙、旧报告缺路径或属于其他契约时退出2且不覆盖。无效输入可能留下旧报告，必须看本次退出码及版本 |
| 登记本轮任务 | `work_eval.py arm 契约文件 --session 实际会话ID --turn 实际轮次ID --cwd 启动目录` | 必须从含根标记和标准源码布局的完整 agent-workflow 维护仓库运行，目录属于该项目；单独安装技能时拒绝门禁；session使用字母、数字、下划线或短横线；检查active内的原契约路径、哈希、session、turn | 启动目录 `.codex/work-eval/实际会话ID/active.json`；同轮重登记保留已用续跑次数 |
| 保留未完成退出 | `work_eval.py release --session 实际会话ID --turn 实际轮次ID --cwd 启动目录 --reason external_block --detail 具体阻碍和恢复条件` | 匹配已登记轮次；reason为user_stop/external_block/hard_budget。未完成退出不改成pass | active中的release；报告和缺口仍保留 |
| 检查Stop协议 | `work_eval.py hook`，从stdin传JSON事件 | 仅当前已登记session/turn；首次必要缺口请求block，最多续跑一次；新轮未登记和项目外返回空对象。空响应可能是隔离跳过，不能单独证明任务通过 | 必要时更新continuations；本流程没有安装原生hook，CLI回放不证明宿主会继续执行 |
| 重放局部协议 | `python3 scripts/verify_protocol.py` | 仅维护本流程时从 agent-workflow 根目录运行；最终读取本次report中的cases、pass和脚本版本 | 新的 `.codex/verification/协议回放-时间/`，保留输入、命令、退出码和输出；只验证合成协议 |

所有 `work_eval.py` 入口均为 `python3 /实际技能目录/scripts/work_eval.py`，文件参数与 --cwd 使用已确认的绝对路径。未知输入先看该入口的 `--help`，不要从名字猜行为。

每次验收建立启动目录 `.codex/verification/<task_id>/<唯一run_id>/`，契约、原样评审与报告同目录。score 用 `.work-eval-write.lock` 目录互斥；正常退出释放自己的空锁。进程被强杀可能留下锁，工具不自动删除或接管，改用独立新目录。JSON 与 Markdown 分别写入，不提供崩溃事务保证；中断后必须核对本次退出码和两份报告，不能沿用旧 pass。

## 恢复同一任务

1. 按 [技能的位置与恢复规则](../SKILL.md) 和目标项目约定定位原计划绝对路径，沿用原 task_id；读取现有计划的有效用户原话、最新纠正、task_id、契约路径、未完成项、已尝试路径和下一动作；引用原文件，不另抄一套规格。
2. 核对当前实际工件和会失效的证据，区分旧记录自述与当前可证明的结果；只补变更、失效或仍未验证的部分。
3. 确认用户本轮确实延续该目标；需要修改要求或范围时修订契约，由独立评审重新检查覆盖，旧评审不能沿用。
4. 在局部hook实验中，用实际session/turn对原任务显式arm；不能从“继续”猜宿主turn，也不能把旧门禁套在无关请求。
5. 执行原缺口的下一动作，在独立新 run_id 目录验证受影响结果并重评，将记录绝对路径更新到原计划；必要项全部满足才交付，真实阻碍则保留未完成与恢复条件。

恢复的最小记录直接写进原计划：有效要求和授权、原任务标识、失败/未验证ID与证据、当前版本、已尝试路径及下一动作。没有新建另一套恢复JSON或自动关联器。

## 按失败维护入口

入口、字段或前置条件发生变化时，先复现再改这份索引及相关技能；机械行为变化同步黑盒回放。区分三类问题：说明与实际不符则修说明，验证工具无法可靠观察则修工具，产品结果本身错误则回到执行。不要让工具跳过产品失败后产生pass。

普通任务无需增加完整Feature Map。需要反复操作复杂产品时，在该产品的验证技能中记录已实读的用户入口、前置条件、可重复命令、可观察终态和证据位置；导航图或记忆摘要不能替代实际对象。
