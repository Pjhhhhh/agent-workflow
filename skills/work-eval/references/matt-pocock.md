# Matt Pocock技能按需接入

Matt 技能用于诊断工程问题、将规格拆成可实施任务、按规格修改及核对规范与规格。按当前缺口选择技能，读取其当前有效正文；work-eval 协调任务范围、执行、验收与恢复。

| 当前任务 | 适用技能 | 使用范围 |
| --- | --- | --- |
| 错误、故障或性能回退的诊断 | diagnosing-bugs | 复用已有失败信号，必要时补最小观察，再定位修复；沿用项目测试与运行授权 |
| 需要跨轮实施的规格或计划，用户要求划分任务 | to-tickets | 写入项目既有任务跟踪位置 |
| 规格、票据和验收已明确，进入实施 | implement | 使用当前有效版本，执行必要修改与验证；保留本地适配 |
| 需要审查代码规范与规格，且有明确基点 | code-review | 对照项目规范与原始规格，核查真实 Git 差异及相关上下文 |
| 用户希望选择合适技能或开发路线 | ask-matt | 提供技能与开发路线选择，按用户有效回答确定后续工作 |

依赖项目配置的技能先读取已有 AGENTS 及 docs/agents 约定。首次缺少必要配置且用户要求配置时，调用 setup-matt-pocock-skills，按其流程展示草案并配置项目。技能正文按宿主实际安装位置定位。

实施采用项目有效的测试策略；技能中的 TDD、提交等步骤按当前任务要求及各自授权执行。审查使用原请求、当前工件及证据，复用适合的评审者和仍有效的结果。更新 implement 等本地适配技能时，按[生效状态与配置升级](execution-and-recovery.md#生效状态与配置升级)核对自管内容与实际加载状态。

缺少技能时说明具体缺口，继续使用已有工具完成可做部分；安装按当前授权执行。

## 规格、任务与验收证据

按规格或票据实施、需要跨轮划分任务或逐条核对业务规则时，在原有规格、任务和验收记录中保留对应关系：任务引用所覆盖的规则，验收判据引用对应规则和实际结果证据。优先沿用已有稳定编号；确需逐条追踪而原文无编号时，在既有记录中补充必要编号。简单任务直接修改与核验。

访谈转入实施或交接时，按[需求确认与实施边界](execution-and-recovery.md#需求确认与实施边界)保留有效问答、决定与待决事项，并将已确认要求关联到上述记录。测试与评审采用同一有效要求。

有效纠正改变规则时，保留原要求及纠正，更新任务与验收的对应关系。

## 工程诊断适配

- 证据已定位具体故障环节时，核对下一动作的必要前提：信息不足则作最小判别检查或取得真实信息；信息充分则在已授权且实际可控的范围内执行最小修复。无法直接执行时，给出具体对象、操作、缺失前提及成功或失败信号。根因判断须有能够支持因果关系的证据。
- 已有证据足以支持下一动作时，继续处理原故障；该动作需要完善日志、脚本或工具时，再作相应修改。根据实际依赖及影响范围确定验证对象。
- 修复后重新检查原故障信号，并核对原业务目标所需路径；分别报告局部修复结果与业务完成状态，保留必要未验证项及下一动作。
