# Matt Pocock技能按需接入

work-eval负责当前任务的范围、验证、回修和交付，Matt技能提供适用的工程方法。没有对应需要时直接工作；用户明确指定技能时按其要求使用。读取专项技能前确认文件可读及适用分支，只有文件存在不能证明宿主已发现或实际调用。

| 当前任务 | 适用技能 | 使用范围 |
| --- | --- | --- |
| 难复现的错误、间歇故障或性能回退 | diagnosing-bugs | 先建立能观察原问题的反馈，再定位修复；沿用项目测试与运行授权 |
| 需要跨轮实施的规格或计划，用户要求拆分 | to-tickets | 写入项目既有任务跟踪位置；简单任务不拆票 |
| 规格、票据和验收已明确，进入实施 | implement | 使用当前有效版本，执行必要修改与验证；保留本地适配 |
| 用户要求代码规范与规格审查，有明确基点 | code-review | 核查真实Git差异和规格；结果供本任务验收使用 |
| 用户希望选择合适技能或开发路线 | ask-matt | 用作用户选择入口；不把推荐的完整阶段自动加入当前任务 |

依赖项目配置的技能先读取已有AGENTS及docs/agents约定。只有首次缺少必要配置、且用户要求配置时才调用setup-matt-pocock-skills；它按自己的流程展示草案并配置项目，不在日常任务中重复运行。技能正文路径按宿主实际安装位置解析，不使用维护者私人绝对路径。

本地自管implement优先保留，不用整包安装或更新覆盖。上游implement的TDD和Git提交步骤不改变本项目或目标项目的有效策略与权限。需要代码审查时复用适合的独立评审者和现有证据，不对同一范围无故重复审查；已有审查只在原请求、当前工件及证据均得到核对时才能沿用，正式v3判断仍按[输入协议](rubric.md)提交。

缺少技能时说明具体缺口，继续用已有工具完成可做部分；安装需当前授权。文档填写、电脑操作和普通研究不套用工程主流程，也不因此增加图集、票据或代码审查。

来源核对：2026-10-05，上游版本4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d；入口和安装方式见[官方README](https://github.com/mattpocock/skills/tree/4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d)。这是本项目的按需适配，不是上游完整流程，也未比较不同技能组合的模型效果。
