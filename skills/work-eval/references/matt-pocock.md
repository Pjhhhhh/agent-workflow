# Matt Pocock技能按需接入

work-eval 负责任务范围、验证、修复和交付，Matt 技能提供适用的工程方法。用户指定技能或当前任务需要对应方法时，读取该技能的当前有效正文，按适用分支执行。

| 当前任务 | 适用技能 | 使用范围 |
| --- | --- | --- |
| 错误、故障或性能回退的诊断 | diagnosing-bugs | 复用已有失败信号，必要时补最小观察，再定位修复；沿用项目测试与运行授权 |
| 需要跨轮实施的规格或计划，用户要求划分任务 | to-tickets | 写入项目既有任务跟踪位置 |
| 规格、票据和验收已明确，进入实施 | implement | 使用当前有效版本，执行必要修改与验证；保留本地适配 |
| 用户要求代码规范与规格审查，有明确基点 | code-review | 核查真实Git差异和规格；结果供本任务验收使用 |
| 用户希望选择合适技能或开发路线 | ask-matt | 提供技能与开发路线选择，按用户有效回答确定后续工作 |

依赖项目配置的技能先读取已有 AGENTS 及 docs/agents 约定。首次缺少必要配置且用户要求配置时，调用 setup-matt-pocock-skills，按其流程展示草案并配置项目。技能正文按宿主实际安装位置定位。

更新 implement 前，核对并保留本地自管内容，合并已获授权的更新。TDD 和 Git 提交步骤按目标项目的有效策略及当前授权执行。需要代码审查时，核对原请求、当前工件及证据，复用适合的评审者和仍有效的审查结果。选用记录检查 CLI 时，按[输入协议](record-checking-protocol.md)提交结构化记录。

缺少技能时说明具体缺口，继续使用已有工具完成可做部分；安装按当前授权执行。文档填写、电脑操作和普通研究按 work-eval 的对应分支执行。

来源核对：2026-10-05，上游版本 4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d；入口和安装方式见[官方 README](https://github.com/mattpocock/skills/tree/4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d)。

## 规格、任务与验收证据

按规格或票据实施、需要跨轮划分任务或逐条核对业务规则时，在原有规格、任务和验收记录中保留对应关系：任务引用所覆盖的规则，验收判据引用对应规则和实际结果证据。优先沿用已有稳定编号；确需逐条追踪而原文无编号时，在既有记录中补充必要编号。简单任务直接修改与核验。

访谈转入实施或交接时，在上述记录中连同问题保留有效回答，区分明确接受的选择、未接受的推荐和待决事项，保留局部纠正后仍有效的决定。新增业务条件及测试、评审判断按[需求确认与实施边界](execution-and-recovery.md#需求确认与实施边界)核对。

有效纠正改变规则时，保留原要求及纠正，更新任务与验收的对应关系。完成情况直接核对当前工件、必要差异和实际结果，复用仍适用且未受影响的证据。

## 工程诊断适配

- 证据已定位具体故障环节时，核对下一动作的必要前提：信息不足则作最小判别检查或取得真实信息；信息充分则在已授权且实际可控的范围内执行最小修复。无法直接执行时，给出具体对象、操作、缺失前提及成功或失败信号。根因判断须有能够支持因果关系的证据。
- 已有证据足以支持下一动作时，继续处理原故障；该动作需要完善日志、脚本或工具时，再作相应修改。根据实际依赖及影响范围确定验证对象。
- 修复后重新检查原故障信号，并核对原业务目标所需路径；分别报告局部修复结果与业务完成状态，保留必要未验证项及下一动作。
