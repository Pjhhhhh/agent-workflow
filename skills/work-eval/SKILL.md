# 工作流程

编辑已有文件时，以原文件为基线，只改变任务要求的内容，默认保留文件类型、结构、样式、公式、编码与换行约定。工具保存可能改变受保护部分时，先核对能力并选择能保留它们的编辑方式。

## 先判断任务分支

- 纯问答、状态查询和流程讨论：按宿主当前有效的全局要求直接回答。
- 受委派的只读调查或评审：按父任务约定返回结论、证据位置和待验证项，由父代理保存并核对整体结果。明确选用记录检查 CLI 时采用其 JSON 格式。
- 简单实质任务：目标和授权明确、影响可控、终态可直接核验且证据一致时，直接执行并保存必要结果。
- 复杂任务：需要多阶段探索且终态无法直接核验、必须跨阶段保留长上下文或状态才能完成必要验收、存在关键证据冲突，或涉及高影响且难回退的变更。沿用相关计划和必要证据，按实际依赖与风险安排核验。

按必要结果的风险、依赖关系和终态可核验性分流，完整满足当前要求。用户或项目明确要求独立评审时执行相应复核；任务复杂度变化时采用对应分支。

## 执行原则

完整承担当前任务，执行必要工作，核验实际结果后交付。

- 完整完成有效要求与已有支持承诺，新增工作具有当前用途。
- 校验、异常处理及恢复对应真实输入或义务，保留权限、数据和安全保障，真实失败明确呈现。
- 按当前请求确定只读或执行职责，修改限于已有授权及必要关联，采用最新文件和有效纠正。
- 复用有效上下文与证据，变化、失败或未解问题触发相关核验，必要结果完成后结束。

按宿主有效规则表达，直接说明结果、必要依据及影响使用的缺口，保留准确的归属与确定程度。途中问题答复后继续原任务；缺少真实信息、业务选择或新权限时，只暂停相关部分。

各实质分支按原目标、职责、完成方式和专项技能要求核验结果。涉及已定业务决定或新增条件时，按[需求确认与实施边界](references/execution-and-recovery.md#需求确认与实施边界)核对有效回答及依据。失败、待验证或评审分歧按[回修与跨轮恢复](references/execution-and-recovery.md#回修与跨轮恢复)处理。来源对应同一对象与版本，事实、推断和未知分别表述；文档核对内容、可编辑性与相关版式，电脑操作检查实际状态，研究保留关键来源。

填写或修订既有文档、使用模板或参考资料、处理叠压与分页等显示问题时，先按[文档模板核验](references/execution-and-recovery.md#文档模板核验)核对原件、输出副本与允许改动；简单任务同样适用。交付文件或修订既有交付时，按[交付位置与修订](references/execution-and-recovery.md#交付位置与修订)核对当前有效文件及历史文件的归属。

测试结束时，按[测试产物收尾](references/execution-and-recovery.md#测试产物收尾)核对保留内容、清理范围及引用。

执行已获授权的Git提交或推送前，按[Git提交与推送范围](references/execution-and-recovery.md#git-提交与推送范围)核对共享内容、暂存差异及推送范围。

## 工具选用与协作

编写或改写代理规则、技能及其引用的代理文档时，按[代理文档写作分支](references/optional-integrations.md#writing-for-agents代理文档写作)读取专项技能或处理缺失，再编辑与核验。

按任务需求、交付格式与可编辑性选择工具，复用已有实现、图源和证据，按需要组合互补能力。独立工作可以并行，共享修改与有依赖的步骤按顺序执行；每个技能读取当前分支所需资料。处理长材料、截断输出、交接或任务恢复时，采用[长输出与摘要](references/execution-and-recovery.md#长输出与摘要)的读取方法。执行与验收遵守目标项目规则和现有授权。

需要工程诊断、跨轮任务安排、按规格实施或代码审查时，按[Matt Pocock接入规则](references/matt-pocock.md)选择对应技能。专项技能的结果进入当前任务验收，沿用已有计划、证据及项目的测试、文件保护和操作权限。

其他技能、插件及 CLI 按用户指定、项目要求或实际能力需要，查[可选接入说明](references/optional-integrations.md)。需要理解系统时选用其中的 Understand-Anything 分支，发布产物与专门运行时取证使用 REA 分支，OCR 审查采用对应模式。必要工具存在使用问题时，按实际影响处理并继续独立工作。

可独立推进且并行有收益时，在已有授权内分配执行者。主会话提供原始要求、有效纠正、目标、权限边界、必要验收和上下文，明确读写路径、产物与依赖。共享目标顺序写入，上下文继承方式按任务需要选择。

执行者完成授权工作与自检，在阶段变化或受阻时报告实际进展，返回结论、工件位置、必要版本信息、证据及未完成项。主会话依据原要求检查决定性证据，核实反馈；可修问题交回具体目标与依据，修改后复验受影响部分。作者自检、主会话核对和独立评审分别按实际参与方式记录，沿用仍有效的检查。

耗时工具支持原生后台句柄、实际转后台，或涉及超时、取消、重试与跨会话恢复时，按[后台执行与恢复](references/execution-and-recovery.md#后台执行与恢复)记录归属、核对实际状态并接回原任务。

## 区分技能位置与任务位置

- **技能目录**：当前 `SKILL.md` 所在的真实目录，脚本位于其 `scripts/work_eval.py`，参考路径相对各文件解析。符号链接先解析真实位置。
- **启动目录**：任务开始时的实际工作区，记录其绝对路径。计划沿用原任务或目标项目约定；没有约定时采用启动目录的 `.codex/plan/<任务>/`。
- **验收目录**：已有计划、日志和交付物足够时直接沿用。需要独立运行记录时采用启动目录的 `.codex/verification/<task_id>/<唯一run_id>/`，保留旧记录。业务交付物放在指定位置，私人材料保存在业务工作区。
- **恢复**：按用户指定路径、计划中的路径或项目约定定位原任务，核对有效要求、任务标识、授权、当前文件、未完成项和下一动作；路径有歧义时确认对应任务。

技能位置以宿主提供的当前 `SKILL.md` 路径为准；若安装在 `~/.agents/skills/work-eval`，可用以下命令解析，其他安装位置替换为实际路径：

```sh
python3 -c 'from pathlib import Path; print(Path("~/.agents/skills/work-eval").expanduser().resolve(strict=True))'
```

该命令返回技能目录；任务文件仍保存到启动目录。脚本使用 Python 3.9+ 和标准库。安装存在问题时说明具体原因，继续可完成的工作与验证。

## 按实际要求核验与交付

1. **明确完整责任。** 从原请求、有效纠正和专项技能中确定必要结果、职责与权限，将用户已给的失败例、必要调用场景与检查范围纳入验收目标，在已有材料中保留依据。分别核对文档内容、格式、结构和获准的调整。
2. **执行并验证。** 直接打开交付物、读取实际字段或状态，按项目策略运行真实行为检查。生成文件修改源后重新生成；打包、服务及外部调用按现有授权执行。
3. **按需要复核。** 用户或项目明确要求，或存在高影响、难以恢复、关键证据冲突时，安排只读独立复核。评审者直接读取原要求、有效纠正、工件与差异，自行判断应达结果，并按[主张核查](references/execution-and-recovery.md#主张核查)核对验收目标、实际检查与证据的对应关系。继续处理可修问题，判据问题按[判据更正](references/execution-and-recovery.md#判据更正)核实并复验。
4. **按实际结果交付。** 依据实际检查覆盖及其证据判断必要结果与检查是否完成，完成后结束，说明仍影响使用的失败或未完成项。沿用有效证据，变化使结论失效时复验相关内容。必要独立复核暂时无法执行时，保留具体原因、未完成状态与恢复条件。

默认直接核验实际结果，沿用已有计划、必要日志和交付物。显式选择记录检查 CLI 时，再读[功能入口](references/cli-reference.md)和[输入协议](references/record-checking-protocol.md)，按其要求准备和核对记录。

代码任务在负责未知输入的边界校验，内部使用已建立的约定；异常处理承担恢复、语义转换、必要上下文或边界展示，意外失败明确呈现。主函数清楚展示主要成功路径，单次 helper 按概念和当前用途决定；注释解释非显然意图或约束，沿用署名及项目约定。生成文件修改源后重新生成，复用现有工具和实现，测试真实行为并遵守当前用户的测试限制。

更新工作流、技能、代理规则或运行配置，或遇到配置变更、恢复异常与第三方升级时，按[生效状态与配置升级](references/execution-and-recovery.md#生效状态与配置升级)核对加载层级、定制差异及复读或重启要求；未核验的热加载保留未知。

## 可选 hook 实验

hook 用于维护项目内明确授权的实验。选用时读取[功能入口](references/cli-reference.md)，核对命令、前提与结果；安装及启用按专项授权执行。
