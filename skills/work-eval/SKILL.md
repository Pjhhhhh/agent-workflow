# 默认工作流程

编辑已有文件时，以原文件为基线，只改变任务要求的内容，默认保留文件类型、结构、样式、公式、编码与换行约定。这适用于简单任务和交付副本；“填写、完善、替换示例、参考资料”本身不授权重建模板、转换格式或美化排版。专项技能按编辑分支使用，额外改进先记录为建议；工具保存可能改变受保护部分时，先核对能力并选择能保留它们的编辑方式。填写或出现叠压、断页、重复页码时，按[已有文件与模板核验](references/safety.md#文档模板核验)核对原话、适配权限和最小修复，避免擅改或反复确认。

交付文件前，查看实际交付目录，明确当前有效文件的位置；修订沿用约定的交付路径与命名，不反复另建“最终版”。区分源模板、历史交付和本次结果，旧文件按已有权限处理；没有移动或删除授权时保留原处并明确其路径与用途，不能让用户靠文件名或日期猜版本。简单任务直接说明，复杂任务写入现有验收，不另建版本管理机制。

## 先判断任务分支

- 纯问答、状态查询和没有实质工作的流程讨论：直接回答，不生成验收记录。
- 受委派的只读调查或评审：按父任务约定返回结论、证据位置、未验证项；正式 v3 评审返回完整 JSON 和实际计算的哈希。父代理保存原判断并完成整体验收；子代理不再建立计划、契约、门禁或递归评审链。
- 简单实质任务：目标和授权明确、最多三个主要步骤、终态可直接核验，且没有关键证据冲突。直接执行并保存必要终态证据；无需新建契约、原要求文件或运行 `score`。
- 复杂任务：超过三个主要步骤、需要研究探索、跨阶段长上下文，或存在关键证据冲突。沿用相关计划，执行下述 v3 验收。分流不缩减必要结果；任务增加实质复杂度时转入相应分支。

图集、Graphify、Archify 和其他专项工具按实际任务选用，不是本流程的前置条件。遵循目标项目的有效规则和用户授权；项目另有明确验收约定时按该约定执行并说明本次采用的方式，不为使用本技能改写业务项目规则。

## 区分技能位置与任务位置

- **技能目录**：当前 `SKILL.md` 所在目录；从符号链接读取时，先解析其真实位置。脚本为此目录的 `scripts/work_eval.py`，参考链接均按各文件的真实位置解析。读取维护资料不改变工作区，也不把维护项目的 AGENTS.md、计划或业务授权带入当前任务。
- **启动目录**：本任务实际工作区的起始目录，记录绝对路径，后续 `cd` 不改变它。计划优先沿用原任务记录或目标项目的约定；没有约定时放启动目录 `.codex/plan/<任务>/`。不要求业务项目使用维护项目的 `.plan/` 或 `.agent-workflow-root`。
- **验收目录**：启动目录 `.codex/verification/<task_id>/<唯一run_id>/`，每次验收或重评用新目录并保留旧记录。业务交付物仍放用户指定位置，私人原话和证据不写进共享技能目录。
- **恢复**：先读用户指定或计划已记录的原计划路径，再按当前项目约定定位；核对有效要求、原 task_id、授权、失败项、尝试和下一动作。路径不唯一才澄清，不能把另一会话的目标带入。

本机安装入口是 `~/.agents/skills/work-eval`。需要定位时执行：

```sh
python3 -c 'from pathlib import Path; print(Path("~/.agents/skills/work-eval").expanduser().resolve(strict=True))'
```

把结果作为技能目录，不将它作为业务工作区。安装不可用时报告具体缺口，继续可做的业务工作与真实验证；不能声称已完成脚本验收。Python 3.9+，无需第三方包。

## 复杂任务的 v3 验收

进入此分支才读 [输入协议](references/rubric.md) 和 [防编造与范围核查](references/safety.md)；调用 CLI 或恢复失败记录时按需读 [功能入口](references/features.md)。新任务不填写旧五维分数。

1. **固定必要要求和权限。** 在原计划写清可验证结果；在当前独立验收目录保存契约、必要用户原话及有效纠正。编辑既有文档时，将保留格式与结构列为必要项，记录允许的具体例外；原件和副本分别验收。request_artifact 纳入 artifacts；scope.allowed_actions 用原话依据记录精确目标和实质操作。计划记录本次验收目录的绝对路径。
2. **执行并验证实际终态。** 完成获授权工作，保留必要差异、日志及可复现证据，准备待交付答复。沿用用户的测试策略，不为验收擅自新增单元测试、打包、服务或外部调用。
   填写或修订既有文档时，先固定原模板与允许改动范围，按相关风险对照输出副本的工作表、栏目、公式、合并、样式及分页；“原文件未改”与“输出没有乱码”不能替代保留格式验收。删除示例内容不自动授权重排版、删公式或新增栏目；有格式转换需要时先核对目标格式与既有授权。具体要求见[文档模板核验](references/safety.md#文档模板核验)。
3. **独立核对并回修。** 向只读评审者直接提供原请求、纠正、契约、待交付答复、实际工件和操作记录；先查漏项，再查完成、来源和授权语义。对照前后差异核查同一文件内的内容、结构与样式变化，以及额外交付物；文件路径获准不代表其中所有改动获准。父代理原样保存返回 JSON 为 judgment.json，不代写结论。仍可推进的缺口继续修复，更新受影响工件后用新 run_id 重评。
4. **运行脚本并交付。** 用技能目录的脚本与本任务契约、评审绝对路径运行 `score`，核对退出码、任务和文件哈希。必要项通过才记为完成；独立代理不可用时注明 self，最多 provisional。真实外部阻碍、用户停止或硬预算时保留未完成和恢复条件。交付后实质工件变化，重新核验受影响项。

独立评审启动失败时，记录真实报错、尝试及影响范围。容量不足不等于配置错误，不规定必须重试三次；相同条件持续失败时停止重复启动，继续可做的实际验证。不能为补审擅自切换模型、供应商或权限。无法取得独立判断时保存 self 与具体恢复条件，交付分清“业务自检结果”和“独立验收未完成”；恢复后沿用原任务，在新 run_id 读取当前工件并补审。

```sh
python3 /实际技能目录/scripts/work_eval.py score /实际验收目录/contract.json /实际验收目录/judgment.json
```

退出码：0=pass；1=有效结果但 fail / partial / provisional；2=输入或读取错误。报告写在契约目录。脚本检查结构、版本、正文引文和已声明操作；语义、记录完整性与评审者身份仍需独立核对。验收通过不授予新权限，也不证明编造率为零。

更新工作流、技能、代理规则或运行配置后，交付时说明生效方式：只改脚本时标明下次调用使用新版；修改已加载的说明时要求相关会话重读；修改启动时读取的规则或配置时说明是否建议或需要重启 Codex。未实际核验热加载就保留未知，不能将文件保存视为在途会话已采用新版。重启前保存当前计划、未完成项与证据，恢复后只核对受影响部分。

## 可选 hook 实验

默认工作方式由全局规则要求代理调用本技能，不依赖 Stop 或自动调度器。`score` 可在不同工作区运行；`arm`、`release` 和 `hook` 仍仅供维护项目内明确授权的实验，见 [功能入口](references/features.md)。不默认安装全局 hooks 或角色；其他项目无需登记门禁。Stop 最多请求继续一次，空响应不能当作验收通过。
