# 文档编写与维护

按宿主或项目规则定位并读取适用的文档规范；未配置专项规范时，沿原请求和既有项目约定执行。审阅按请求保持只读，编写、填写或修改以用户要求的文档及范围为对象。

局部文档任务围绕目标正文，读取判断其用途所需的相邻内容、同级标题、直接依据和相关引用；集中整理按下述分支扩大阅读路径。填写或修订既有文件、使用模板、处理版式或可编辑性时，读取[既有文件、模板与交付检查](references/file-editing.md)。

编写或改写技能、`AGENTS.md` 等代理文档时，使用当前可用的 writing-for-agents；技能文档同时读取其 `SKILL-MECHANICS.md`。没有该技能时，按适用文档规范继续处理。

## 编写与局部处理

1. **确定读者问题。** 明确文档及各节的实际受众角色、当前使用情境和要完成的任务，确定文体及本次成稿、改动或审阅的范围。
2. **核对来源。** 核实正文所需来源、真实填写信息和适用条件，区分当前事实与历史材料。行为、命令和配置对照当前实现或实际结果；业务目标与状态对照有效要求及实际记录。来源冲突时核对对象、版本和适用范围，按证据保留具体冲突与未知。
3. **安排内容与标题。** 逐节区分当前使用者完成页面任务所需的内容、维护者内部事项及仅特定分支所需的参考内容，按实际受众与触发条件安排正文、概览和参考；条件参考在触发处给出简短含义与链接，正文必要条件保留在相关操作旁。对照同级标题所指对象与各节实际范围，核实并列、包含或条件分支关系，据此调整标题、层级与内容归属。
4. **逐段取舍。** 在本次范围内逐节、逐段检查，每段逐句判断其内容如何帮助本节读者。对导航、规则提醒及其他补充，结合相邻正文和导航目标，比较去掉后会失去的具体信息、独立入口或必要条件，以及保留它增加的阅读负担；独立阅读路径需要的提示保留在相关操作旁。重复信息在负责该主题的位置集中维护。
5. **组织表述。** 当前说明先讲用途、行为与必要条件，再给实现细节；示例提供可使用的成稿。稳定操作步骤、对外引用 ID 和 API 版本保留名称及上下文；研究与历史记录保留解释决定所需的时间、状态和依据。编辑、选型及起草经过留在任务材料中。完成内容取舍后再润色表达。
6. **检查格式与导航。** 分别核对自然语言和命令、代码块、字段、枚举、路径、链接及显式 ID，保留精确名称与有效含义。检查本次涉及的引用、锚点和入口是否对应当前目标，按读者查找需要维护既有导航；文件格式与版式按上述文件检查参考处理。
7. **核对最终文件。** 以最终采用文件为对象，对照原请求和适用规范检查必要信息、内容归属、表达与格式，沿涉及的入口、导航和正文完成读者任务，核对字段、来源、必要条件及结果判断。路径可用与内容、组织质量分别判定；用户已给的失败例和必要触发场景用于对应检查。复用旧稿结果前核对最终文件，变化时复查受影响内容。只读审阅返回经核实的问题、上下文依据及其对理解或操作的影响。

## 按需集中整理

1. **确定范围。** 优先采用用户命名的文档或主题；未指定时，从现有入口与近期实际变更定位范围。用户要求全部文档时，按实际目录枚举项目文档，纳入未跟踪和被忽略的文档，并找到生成页面对应的源文件。工作区有未提交修改时，以当前内容为基线。涉及术语或架构决定时读取相关术语表与决策记录。
2. **沿阅读路径找问题。** 逐页、逐节确定读者当前要回答的问题，采用上述内容归属与取舍方法，检查各页承担的问题及页间依赖，定位遗漏、重复、归属不当或状态不一致的内容。
3. **核对并排序。** 将候选与当前有效要求、实现及历史决策对应，区分页面取舍问题、文档漂移、验证工具缺口和产品缺陷。实现与业务意图不一致时核对依据，业务含义未明则保留具体冲突，不把实现中的差异写成业务规则。按读者影响排序，写清位置、影响和最小处理。
4. **复查相关路径。** 按上述最终文件核对方法检查本次涉及的阅读或操作路径，检查跨入口、相邻页同一信息的表述与归属是否一致，确认读者能找到、理解并使用内容。全量任务对照文件范围确认每份文档均已核对。需要按章节分组检查整页时，各组保留相邻正文、同级标题和必要导航上下文，汇总时标明未覆盖范围。重要新文档或较大整理缺少读者视角时，可让未参与写作的读者只看成稿回答实际问题，检查隐含前提与矛盾。
