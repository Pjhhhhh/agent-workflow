# 文档编写与维护

开始时按当前宿主或项目规则定位并读取适用的文档规范，核对原请求、有效项目规则和允许改动。未配置专项文档规范时，沿原请求和既有项目约定执行，不自行复制或创建 DOCUMENT.md。审阅按请求保持只读，获准编写或修改时完成相应处理。

依据当前请求选择分支；为其他工作阅读资料时沿用原任务范围。局部文档任务围绕目标正文，读取判断其用途所需的相邻内容、同级标题、直接依据和相关引用，集中整理才扩大阅读路径。

## 编写与局部处理

1. **确定读者问题。** 明确这份文档及各节要帮助谁解决什么问题，以及本次成稿或改动的范围。
2. **核对来源。** 核实正文所需来源、真实填写信息和适用条件，区分当前事实与历史材料；影响目标、真实信息或权限的缺口按原请求处理。
3. **逐节检查并取舍。** 按读者用途与文体组织成稿，或在请求范围内处理已有文档。当前说明和示例直接呈现最终有效的功能、行为、适用条件、真实状态及必要依据，先说明用途和条件，再给必要实现细节；示例直接提供读者可使用的成稿。编辑、选型和起草经过留在原任务材料。稳定操作步骤、对外引用 ID 和 API 版本保留名称及必要上下文；研究与历史记录保留解释相应决定所需的时间、状态和依据。在本次范围内逐节核对标题与各段；每段逐句检查，段落已有用途时也分别判断其中的补充。对导航、规则提醒或其他补充，在阅读比较中暂时排除该项，明确读者会失去哪项事实、解释、条件、动作、风险或独立入口，再沿相邻正文与导航目标确认这些信息是否已提供；只读任务仅作比较，不实际改文。结合具体信息损失、快捷定位用途、独立阅读路径的需要与增加的阅读负担，决定保留或按授权合并、精简。解释与历史材料的知识用途同样纳入判断；告警与必要条件保留在相关操作旁。内容取舍完成后再润色；完成本次范围内各节的内容检查后汇总结果，只读审阅返回经核实的内容与组织问题及上下文依据，按增加阅读负担、影响对象选择或阻断操作等实际后果说明影响。
4. **核对标题与最终文件。** 对照同级标题所指对象与各节实际覆盖范围，核实它们的并列、包含或条件分支关系；名称与范围的差异有真实关系依据时保留，否则在授权内修正标题、层级或内容归属。以最终采用文件为对象，对照原请求和适用规范，分别核对必要信息是否齐全，以及已包含内容是否存在有上下文依据的重复、旁支或覆盖范围问题。沿本次涉及的入口、导航和正文完成读者任务，核对字段、来源、必要条件及结果判断；路径可用与内容、组织质量分别判定，已证实的内容或组织问题纳入审阅结果。将用户已给的失败例和必要触发场景用于这次检查。复用试用稿或旧版的结果前，核对最终文件的内容和组织；变化时复查受影响路径，未受影响的有效结果继续复用。

## 按需集中整理

1. **确定范围。** 优先采用用户命名的文档或主题；未指定时，从现有入口与近期实际变更定位范围。用户要求全部文档时，按实际目录枚举项目文档，纳入未跟踪和被忽略的文档，并找到生成页面对应的源文件。工作区有未提交修改时，以当前内容为基线。涉及术语或架构决定时读取相关术语表与决策记录。
2. **沿阅读路径找问题。** 逐页、逐节确定读者当前要回答的问题，采用局部处理中的组织与取舍方法。检查概览是否先解释用途与行为、当前说明是否按功能和实际适用条件组织、旧状态是否混作现状，以及限定、来源、示例或个人工具组合是否帮助当前任务。先处理内容取舍，再修改措辞；在获准重组的范围内删除无用途内容，必要规则在负责该主题的文档集中维护，其他入口保留当前查阅所需的摘要或链接。
3. **核对并排序。** 将候选与当前有效要求、实现及历史决策对应，区分页面取舍问题、文档漂移、验证工具缺口和产品缺陷。研究正文采用对应日期的有效结论，保留有解释用途的历史决定，起草失误与改写经过留在任务记录中。实现与业务意图不一致时核对依据，业务含义未明则保留具体冲突，不把实现中的差异写成业务规则。复核受影响部分和上轮未决问题，沿用有效依据，按读者影响排序，写清位置、影响和最小处理。
4. **按授权处理。** 在已授权范围内按适用规范的写作与修复要求处理已证实的页面取舍、表述和导航问题；只有业务选择、无法确认的现状或超范围动作需要询问。等待时继续无依赖的工作。
5. **复查相关路径。** 按上述最终文件核对方法检查本次涉及的阅读或操作路径，并检查跨入口、相邻页同一信息的表述与归属是否一致，确认原目标与必要使用条件得到保留，读者能找到、理解并使用内容。全量任务对照文件范围确认每份文档均已核对。收到反例时，核实其对应的当时有效要求、对象和版本；确认漏检后，重新核对受影响的通过结论，并在原范围内复查同类原因后修复、复验；若漏检来自整页审阅，按章节分组回查，各组保留相邻正文、同级标题和必要导航上下文，分别完成后汇总，并标明未覆盖范围。重要新文档或较大整理缺少读者视角时，可让未参与写作的读者只看成稿回答实际问题，检查隐含前提与矛盾后修订。没有实际问题时保留原文并结束。

交付文字直接给出最终有效结果、必要依据及影响使用的真实状态，编辑经过留在原任务材料。需要成稿形式参考时，按需读[成稿示例](references/examples.md)；检查或调整本技能的设计依据时，读[来源与采用理由](references/sources.md)。
