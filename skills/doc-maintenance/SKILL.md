# 文档编写与维护

开始时按当前宿主或项目规则定位并读取适用的文档规范，核对原请求、有效项目规则和允许改动。未配置专项文档规范时，沿原请求和既有项目约定执行，不自行复制或创建 DOCUMENT.md。审阅按请求保持只读，获准编写或修改时完成相应处理。

依据当前请求选择分支；为其他工作阅读资料时沿用原任务范围。局部文档任务只检查目标正文、直接依据和相关引用，集中整理才扩大阅读路径。

## 编写与局部处理

1. **确定读者问题。** 明确这份文档要帮助谁完成什么，以及本次成稿或改动的范围。
2. **核对来源。** 核实正文所需来源、真实填写信息和适用条件，区分当前事实与历史材料；影响目标、真实信息或权限的缺口按原请求处理。
3. **组织或处理正文。** 按读者用途与文体组织新稿，或在请求范围内处理已有文档。逐句判断谁会使用、改变哪项理解或操作，以及删去是否造成具体事实或操作错误，据此删除无用途内容、改写表达不准的内容、将必要条件移到相关操作旁或保留必要信息；一个自然段已有用途时，也分别判断其中的补充。只读审阅返回经核实的问题与依据。
4. **按用途复核。** 对照原请求和适用规范重新阅读成稿，包括标题与简介、表格说明、段尾补充和交付文字，确认内容回答读者问题、保留必要信息，删改后仍满足原目标和必要使用条件，并核对本次涉及的字段、来源及阅读路径。

## 按需集中整理

1. **确定范围。** 优先采用用户命名的文档或主题；未指定时，从现有入口与近期实际变更定位范围。工作区有未提交修改时，以当前内容为基线。涉及术语或架构决定时读取相关术语表与决策记录。
2. **沿阅读路径找问题。** 先确定每页读者当前要回答的问题，再按编写与局部处理中的逐句方法判断内容在此页的用途。检查概览是否被实现标识符挤满、临时阶段或未来方向是否缺少上下文、旧状态是否混作现状，以及限定、来源、示例或个人工具组合是否帮助当前任务。指出具体阅读障碍；在获准重组的范围内，将重复或旁支列为删除、移到相关页面或改成已有参考入口的候选，保留有用途的内容。
3. **核对并排序。** 将候选与当前有效要求、实现及历史决策对应，区分页面取舍问题、文档漂移、验证工具缺口和产品缺陷。实现与业务意图不一致时核对依据，业务含义未明则保留具体冲突，不把实现中的差异写成业务规则。复核受影响部分和上轮未决问题，沿用有效依据，按读者影响排序，写清位置、影响和最小处理。
4. **按授权处理。** 在已授权范围内按适用规范的写作与修复要求处理已证实的页面取舍、表述和导航问题；只有业务选择、无法确认的现状或超范围动作需要询问。等待时继续无依赖的工作。
5. **复查相关路径。** 沿涉及的阅读或操作路径核对结果，并检查跨入口、相邻页同一信息的表述与归属是否一致，确认原目标与必要使用条件得到保留，读者能找到、理解并使用内容。重要新文档或较大整理缺少读者视角时，可让未参与写作的读者只看成稿回答实际问题，检查隐含前提与矛盾后修订。没有实际问题时保留原文并结束。

交付实际变化及其影响。表述取舍难以判断时，按需读[教学示例](references/examples.md)；检查或调整本技能的设计依据时，读[来源与采用理由](references/sources.md)。
