# 文档编写与维护

按宿主或项目规则定位并读取适用的文档规范；未配置专项规范时，沿原请求和既有项目约定执行。审阅按请求保持只读，编写、填写或修改以用户要求的文档及范围为对象。

正式文档和代码注释只描述当前有效状态；废弃决定、AI 修改历史、临时开发阶段及起草纠错经过留在任务材料中。未经确认的实现偏差不得写成业务规则。

局部文档任务围绕目标正文，读取判断其用途所需的相邻内容、同级标题、直接依据和相关引用；集中整理按下述分支扩大阅读路径。填写或修订既有文件、使用模板、处理版式或可编辑性时，读取[既有文件、模板与交付检查](references/file-editing.md)。

编写或改写技能、`AGENTS.md` 等代理文档时，使用当前可用的 writing-for-agents；技能文档同时读取其 `SKILL-MECHANICS.md`。没有该技能时，按适用文档规范继续处理。

## 编写与局部处理

1. **读懂现有说明。** 通读本次范围内的现有正文和相邻入口，弄清已有主张、适用条件及各节读者要完成的任务，据此明确受众、使用情境、文体及本次成稿、改动或审阅的范围。
2. **核实内容依据。** 核对必要主张、真实填写信息和适用条件。行为、命令和配置对照当前源码、配置、依赖与运行环境，以及可取得的实际状态；业务含义对照用户已确认的需求和仍有效的决定。存在冲突时核对对象、版本和适用范围，保留影响当前判断或使用的具体冲突与未知。成稿引用按读者核实结论、理解归因或完成操作的需要取舍，放在对应内容旁；核查经过保存在任务记录中。
3. **安排内容与标题。** 按读者任务区分正文必要内容、维护事项和条件参考，正文写清功能及其必要规则，让读者无需依赖临时计划、草稿或尚未实施的设想资料就能理解。任务运行输入、日志与恢复状态属于工作流的实际对象，按任务约定保留。条件参考在触发处给出简短含义与链接，必要条件放在相关操作旁。对照同级标题和各节实际范围，核实并列、包含或条件分支关系，调整标题、层级与内容归属。
4. **逐段取舍。** 更新已确认与当前情况不符的说明，删去失效信息。在本次范围内逐节、逐段检查，每段逐句判断其内容如何帮助本节读者。对导航、规则提醒及其他补充，结合相邻正文和导航目标，比较去掉后会失去的具体信息、独立入口或必要条件，以及保留它增加的阅读负担；独立阅读路径需要的提示保留在相关操作旁。重复信息在负责该主题的位置集中维护。
5. **组织表述。** 用常用词先讲用途、行为与必要条件；必要技术词先说明用途，代码按理解行为或完成操作的需要提供，示例给出可使用的成稿。操作步骤、对外引用的有效 ID、API 版本与兼容条件保留准确名称及上下文。完成内容取舍后再润色表达。
6. **检查格式与导航。** 分别核对自然语言和命令、代码块、字段、枚举、路径、链接及显式 ID，保留精确名称与有效含义。将模糊引用补为可定位的对象、文件、章节或有效链接，核对引用、锚点和入口的目标及其内容是否仍有效；按读者查找需要维护既有导航，文件格式与版式按上述文件检查参考处理。
7. **核对最终文件。** 以最终采用文件为对象，对照原请求和适用规范检查必要信息、内容归属、表达与格式，沿涉及的入口、导航和正文完成读者任务，核对字段、引用、必要条件及结果判断。逐项确认引用直接支持对应主张，并帮助本节读者理解、核实或操作。路径可用与内容、组织质量分别判定；用户已给的失败例和必要触发场景用于对应检查。复用旧稿结果前核对最终文件，变化时复查受影响内容。只读审阅返回经核实的问题、上下文依据及其对理解或操作的影响。

## 按需集中整理

1. **确定范围。** 优先采用用户命名的文档或主题；未指定时，从现有入口与近期实际变更定位范围。用户要求全部文档时，按实际目录枚举项目文档，纳入未跟踪和被忽略的文档，并找到生成页面对应的源文件。工作区有未提交修改时，以当前内容为基线。涉及术语或架构决定时读取相关术语表与决策记录。
2. **沿阅读路径找问题。** 逐页、逐节确定读者当前要回答的问题，采用上述内容归属与取舍方法，检查各页承担的问题及页间依赖，定位遗漏、重复、归属不当或状态不一致的内容。
3. **核对并排序。** 将候选与当前有效要求、实现及有效决定对应，区分页面取舍问题、文档漂移、验证工具缺口和产品缺陷。按读者影响排序，写清位置、影响和最小处理。
4. **复查相关路径。** 按上述最终文件核对方法检查本次涉及的阅读或操作路径，检查跨入口、相邻页同一信息的表述与归属是否一致，确认读者能找到、理解并使用内容。全量任务对照文件范围确认每份文档均已核对。需要按章节分组检查整页时，各组保留相邻正文、同级标题和必要导航上下文，汇总时标明未覆盖范围。重要新文档或较大整理缺少读者视角时，可让未参与写作的读者只看成稿回答实际问题，检查隐含前提与矛盾。
