# 工作流程

work-eval 统筹任务分流、执行协调、验收、复核与恢复。工程推进按需采用 Matt Pocock 技能，结果核验按需采用 pstack 方法，两者沿用当前任务的要求、计划和证据。安装与调用见[安装说明](安装与更新.md)。

只读调查或审查以经核实的结论、问题位置、依据和待验证项为结果；发现问题后的修改需要相应授权。执行任务采用下面的路径。

## 执行任务的完整路径

1. 按[默认工作流技能](../skills/work-eval/SKILL.md)，从原请求和最新纠正确定完整目标、必要结果与授权，沿用已有计划和必要记录。使用旧记忆或外部资料时核对来源；用户追加要求时，核对当前目标和受影响结果。
2. 解决影响目标、必要验收或授权的不确定性，按下面的条件选择工程方法与工具。可逆技术细节沿用已有约定；缺少真实业务信息或新权限时，暂停依赖部分并继续独立工作。复杂任务或恢复需要时，在已有记录中保留当前计划、尝试、证据和下一动作。
3. 观察目标对象的实际终态，按任务类型和验证缺口选择检查方法，验证每条必要结果，保留核验所需的实际差异或工具日志。
4. 核对必要结果、关键主张、实际操作和权限；独立复核按明确要求或高影响、关键证据冲突等实际需要安排。评审者直接读取原要求、当前工件和差异，查找遗漏要求并核对来源是否支持结论。失败或缺少证据时，处理具体缺口并验证受影响部分。
5. 必要项通过后交付。遇到真实外部阻碍、用户停止或预算上限时，记录未完成项、具体原因和恢复条件。

来源、权限与修复核查见[防编造与范围核查](防编造与范围核查.md)。显式使用记录检查 CLI 时，再读[功能入口](../skills/work-eval/references/cli-reference.md)。

## 工程任务怎样选择方法

Matt Pocock 技能为不同工程问题提供专门方法，按当前任务选择对应入口，读取实际已安装版本。完整条件和本地适配见[Matt Pocock 接入规则](../skills/work-eval/references/matt-pocock.md)。

| 当前需要 | 采用的方法 | 结果怎样接回当前任务 |
| --- | --- | --- |
| 定位错误、故障或性能回退 | `diagnosing-bugs` | 用已有失败信号判断下一动作，修复后复验原故障和业务路径 |
| 把规格划分为跨轮实施任务 | `to-tickets` | 写入项目既有任务跟踪位置，保留规则、任务与验收的对应关系 |
| 按明确规格和票据实施 | `implement` | 完成必要修改与验证，遵守项目测试和 Git 操作权限 |
| 对明确基点以来的代码做规范与规格审查 | `code-review` | 读取真实差异和规格，将发现纳入本次修复与验收 |
| 选择开发路线或合适技能 | `ask-matt` | 依据用户有效回答确定采用的路线和后续工作 |

## 结果怎样验证

pstack 方法用于补足实际运行、可重复验证及安全判断中的缺口。先复用项目已有验证入口，再按下面的条件选择能力；具体要求见[pstack 验证与改进方法](../skills/work-eval/references/pstack.md)。

| 当前需要 | 采用的方法 | 应取得的结果 |
| --- | --- | --- |
| 已有 `verify-<app>` | 按项目验证技能驱动实际应用 | 用户路径的可观察终态和证据 |
| 缺少可靠入口且需反复验证应用，或用户明确要求生成 | `create-verification-skill` | 可重复的验证技能，以及其中至少一个功能的真实运行结果 |
| 验证技能或 Feature Map 已失效，或用户要求维护 | `maintain-verification-skill` | 源码与实际交互的覆盖结果，以及需要修复或仍受阻的范围 |
| 报告性能数字或据此比较方案 | `benchmark-checklist` | 条件明确、错误计数与输出正确性可核对的测量结果 |
| 安全判断需要调查局部差异以外的影响 | `blast-radius` | 实际依赖、数据及时序中的风险，及关键判断的运行证据 |
| 同类已证实错误在仓库反复发生 | `correct` | 能检出真实历史错误的可执行约束 |

例如，故障任务可以先用 `diagnosing-bugs` 定位和修复，再通过已有 `verify-<app>` 重走原用户路径。诊断、代码审查和验证得到的结果汇入原任务；是否完成取决于原要求的必要结果及实际证据。

第三方技能的可用版本与安装位置以目标宿主为准。缺少技能时，说明受影响的必要项并继续已有工具可完成的工作；安装按当前授权执行。

## 文档任务怎样处理

文档编写、修改或审阅使用 [doc-maintenance](../skills/doc-maintenance/SKILL.md)，按适用规范处理内容、组织、表达、格式与阅读路径。局部处理围绕指定正文及直接相关内容；集中整理再沿跨页阅读路径检查遗漏、重复、导航与信息归属。

仅使用 doc-maintenance 时，按目标项目规则完成文档任务即可。同时使用两项技能时，由 work-eval 统筹整体任务，采用 doc-maintenance 的专业处理结果完成验收。获准修改时核对最终文档及相关入口；只读审阅时返回问题位置、上下文依据和对读者的影响。

## 各类任务的验收对象

| 任务 | 应观察的终态 | 常见遗漏 | 最小证据 |
| --- | --- | --- | --- |
| 代码 | 目标用户路径得到约定结果，必要既有行为保持；修复任务还须复验原失败输入 | 局部回归通过，但原用户路径未达要求；错误降级掩盖未完成 | 输入、真实结果、trace 或日志、复现命令 |
| 文档 | 编写或修改后，内容准确、必要信息齐全，当前说明与历史状态清楚，格式符合适用要求，相关阅读路径可用；只读审阅交付经核实的问题、位置、依据与影响 | 只核对格式，遗漏内容、读者任务或状态漂移；擅改受保护模板 | 正文与来源对照、相关路径核验；模板、版式与可编辑性要求见[文件编辑与交付](../skills/doc-maintenance/references/file-editing.md) |
| 电脑操作 | 指定程序采用目标配置，实际调用得到约定结果 | 编辑了非生效副本，版本更新但调用仍失败 | 生效路径、原生诊断、前后状态 |
| 研究 | 原问题得到可追溯回答，事实、推断、旧信息和未知明确 | 引文存在但不支持结论；旧摘要升级成当前事实 | 主张对应正文、日期或版本、反证与未知 |
