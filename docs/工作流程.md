# 工作流程

work-eval 用于确定任务范围、执行、核验与恢复；普通问答遵守宿主全局规则直接回答。安装与调用见[安装说明](安装与更新.md)。

只读调查或审查以经核实的结论、问题位置、依据和待验证项为结果；发现问题后的修改需要相应授权。执行任务采用下面的路径。

## 执行任务的完整路径

1. 按[默认工作流技能](../skills/work-eval/SKILL.md)，从原请求和最新纠正确定完整目标、必要结果与授权，沿用已有计划和必要记录。使用旧记忆或外部资料时核对来源；用户追加要求时，核对当前目标和受影响结果。
2. 解决影响目标、必要验收或授权的不确定性，选择对应工具执行。可逆技术细节沿用已有约定；缺少真实业务信息或新权限时，暂停依赖部分并继续独立工作。复杂任务或恢复需要时，在已有记录中保留当前计划、尝试、证据和下一动作。
3. 观察目标对象的实际终态，验证每条必要结果，保留核验所需的实际差异或工具日志。
4. 核对必要结果、关键主张、实际操作和权限；独立复核按明确要求或高影响、关键证据冲突等实际需要安排。评审者直接读取原要求、当前工件和差异，查找遗漏要求并核对来源是否支持结论。失败或缺少证据时，处理具体缺口并验证受影响部分。
5. 必要项通过后交付。遇到真实外部阻碍、用户停止或预算上限时，记录未完成项、具体原因和恢复条件。

来源、权限与修复核查见[防编造与范围核查](防编造与范围核查.md)。显式使用记录检查 CLI 时，再读[功能入口](../skills/work-eval/references/cli-reference.md)。

## 文档任务怎样处理

文档编写、修改或审阅使用 [doc-maintenance](../skills/doc-maintenance/SKILL.md)，先读取宿主或项目配置的文档规范，再核对读者任务、必要信息、内容依据和组织。局部处理围绕指定正文及直接相关内容；集中整理再沿跨页阅读路径检查遗漏、重复、导航与信息归属。

仅使用 doc-maintenance 时，按目标项目规则完成文档任务即可。同时使用两项技能时，work-eval 负责整体范围、执行、验证与恢复，doc-maintenance 负责文档内容和组织的具体处理。获准修改时核对最终文档及相关入口；只读审阅时返回问题位置、上下文依据和对读者的影响。

## 研究进入计划前，核对决定修改的依据

陌生代码链路、来源冲突或跨模块变更需要调查时，在已有任务记录中区分当前事实、推断、未知和拟议方案。方案进入计划前核对三个问题：原请求是否需要这项修改；关于当前链路的判断是否有直接来源；验证动作能否观察原问题的终态。来源写明文件或页面、正文位置及版本，验收要求以原请求和有效纠正为准。

## 四类任务共用流程，采用不同验证

| 任务 | 应观察的终态 | 常见遗漏 | 最小证据 |
| --- | --- | --- | --- |
| 代码 | 原失败输入经过实际用户链路得到约定结果，必要既有行为保持 | 局部回归通过，但原问题仍存在；错误降级掩盖未完成 | 输入、真实结果、trace 或日志、复现命令 |
| 文档 | 编写或修改后，内容准确、必要信息齐全，当前说明与历史状态清楚，相关阅读路径可用；只读审阅交付经核实的问题、位置、依据与影响。有模板或版式要求时，保存后重开或渲染，核对结构、格式、公式和字段 | 只核对格式，遗漏内容、读者任务或状态漂移；擅改受保护模板 | 正文与来源对照、相关路径核验；有模板或版式要求时保留相应输出对照，见[文档模板核验](防编造与范围核查.md#文档模板核验) |
| 电脑操作 | 指定程序采用目标配置，原问题在实际调用中消失 | 编辑了非生效副本，版本更新但调用仍失败 | 生效路径、原生诊断、前后状态 |
| 研究 | 原问题得到可追溯回答，事实、推断、旧信息和未知明确 | 引文存在但不支持结论；旧摘要升级成当前事实 | 主张对应正文、日期或版本、反证与未知 |

## 持续运行长任务

需要宿主持续运行长任务时，按[长任务说明](https://learn.chatgpt.com/docs/long-running-work)选择用户明确要求的入口。

## 图与子代理的用途

需要图示、代码关系或其他工具时，按[可选接入说明](../skills/work-eval/references/optional-integrations.md)选择；已有图示见[流程图集](diagrams/index.html)。

必要的独立复核可交给只读子代理，提供原始要求和实际对象，由父代理保留原判断并核对整体结果。独立范围可并行，共享文件修改与依赖步骤顺序执行，子代理直接返回本次评审结果。
