# 依据与适用范围

核对日期：2026-09-30。以下来源提供方法建议或特定任务上的研究结果，本项目据此处理本地问题。整套 Codex 流程仍需实际检验，本文没有证明 Sol / Astra 在本地的提升比例。

## 论文可以提供什么

| 研究 | 可借用机制 | 不推导的结论 |
| --- | --- | --- |
| [SWE-bench，v3](https://arxiv.org/html/2310.06770v3) | 同时检验原失败修复和既有行为保持 | 基准通过不等于任意完整项目验收 |
| [OSWorld，2024 v2](https://arxiv.org/html/2404.07972v2) | 在实际电脑环境检查文件、配置和应用终态 | 不能自动验证所有 macOS 软件与文档 |
| [MT-Bench / Chatbot Arena，v4](https://arxiv.org/html/2306.05685v4) | 评委校准，警惕顺序、冗长与自我偏好等局限 | 聊天偏好一致性不等于业务正确性 |
| [AI Agents That Matter](https://arxiv.org/html/2407.01502) | 同时比较成本与结果，使用保留集和可复现条件 | 更多循环、更多代理或更高自评分不天然更好 |

以上分别是研究基准或评测方法，版本已限定；本文不引用旧模型榜单为当前能力。已核对论文正文入口，细节适配仍须本地真实任务验证。

## 现成工具的选择

[Promptfoo assertions](https://www.promptfoo.dev/docs/configuration/expected-outputs/)可组合确定性断言与模型量表，适合之后固定一批输入比较模型或技能版本。本项目没有安装或接入 Promptfoo。

[Inspect Scoring](https://inspect.aisi.org.uk/scoring.html)是已有研究阶段考察的备选评测平台，本轮直接打开失败，未重验当前接口。没有必要为了几次本地试验先安装大型框架；需要可重放 agent 环境时再单独评估。

[OpenAI 长任务说明](https://learn.chatgpt.com/docs/long-running-work)解释目标运行机制。普通任务依然能用验收技能，/goal 不是评分前提，本项目也不实现宿主命令。

## 两篇评论文章怎样采用

用户提供的《Loops and Graphs》和《Harness Engineering》将局部修复循环、依赖组织、工具、持久状态和观察分开解释，作为流程设计的启发。文章强调“一个节点失败只返修该节点”和“重要规则有机器检查”，值得按实际问题试验。

本项目尚未实现通用任务调度图、自动权限引擎或自我改进平台。需要梳理依赖时再使用工作图。反复失败时应重新诊断，失败次数本身不能证明计划有错；改进记录应保留适用条件，是否形成长期规则由真实案例决定。

X 来源供定位，本文依据用户给出的正文作评论，不确认当前在线全文与编辑时间：[Loops and Graphs](https://x.com/hanakoxbt/status/2091515787366306154)、[Harness Engineering](https://x.com/0xwhrrari/status/2093685107534000560)。
