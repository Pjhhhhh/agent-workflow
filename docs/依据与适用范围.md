# 依据与适用范围

work-eval 以任务要求、当前工件和实际结果为验收依据。Matt Pocock 技能用于工程诊断、规格实施与审查，pstack 方法用于驱动应用、核对测量和调查变更影响；采用条件见[流程参考与取舍](流程参考与取舍.md)。本页说明验收与效果检验的方法依据。

## 按任务确定验收对象

验收先明确用户需要的结果，再选择能够观察该结果的检查。代码任务核对目标行为与必要回归，电脑操作核对实际文件、配置和应用终态，资料研究核对来源正文与结论，文档任务核对成稿能否支持读者完成任务。

任务特定目标、实际输入与人工校准的依据见 [OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)；过程记录与环境终态的区分见 [Anthropic Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。本项目的确定性协议回放只检查已提交记录及可观察的文件条件，业务结果还须按对应任务实际核验。

## 从真实错误选择检查

失败分析用于确定缺口、下一动作及复验对象。已经修复的原失败输入需要重新验证，必要既有行为也要保持。该做法对应 [SWE-bench](https://arxiv.org/html/2310.06770v3) 对失败修复和回归保持的检查；电脑任务的终态观察参考 [OSWorld](https://arxiv.org/html/2404.07972v2)。

沿实际轨迹定位错误、核对任务分解，再依据效果调整步骤，方法见吴恩达的 [Evals and Error Analysis Part 1](https://www.deeplearning.ai/the-batch/improve-agentic-performance-with-evals-and-error-analysis-part-1/) 与 [Part 2](https://www.deeplearning.ai/the-batch/improve-agentic-performance-with-evals-and-error-analysis-part-2/)。这些方法用于组织检查，不能单独证明本工作流已经改善完成率。

## 校准评审与比较效果

模型评审需要用已知结果和人工样本校准，并检查顺序、篇幅与自我倾向造成的影响；相关研究见 [MT-Bench / Chatbot Arena](https://arxiv.org/html/2306.05685v4)。独立复核按用户、项目要求或实际风险安排，评审者直接读取原要求、当前工件及证据。

比较规则效果时，固定起始案例、必要结果、允许操作、模型、工具与预算，每次改变单个因素，同时统计结果、错误、耗时与成本。固定评测条件与实验记录可参考 [Karpathy autoresearch](https://github.com/karpathy/autoresearch/blob/068d93da75aa45f72ba482046f108241aaaf1b8e/program.md)；保留集、评审校准与单项改变见 [Lance Martin 的 eval 设计方法](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)，成本与结果共同评价见 [AI Agents That Matter](https://arxiv.org/html/2407.01502)。本项目的执行条件和未完成项见[真实任务检验](真实任务检验.md)。

## 使用边界

来源提供可采用的方法，项目效果取决于实际任务与检验结果。合成协议输入、宿主发现技能或一次受控样本通过，各自只支持其覆盖范围。涉及长任务、工具安装、应用操作或外部副作用时，继续采用当前任务的授权和宿主能力；长任务入口的使用条件见 [OpenAI 长任务说明](https://learn.chatgpt.com/docs/long-running-work)。
