# 全局使用范围

安装方式见[安装与更新](安装与更新.md)。下载项目后，需要安装技能并在自己的全局 AGENTS.md 中配置默认入口，才会要求代理在代码、文档、电脑操作和资料研究任务中读取该技能：简单任务直接核验，复杂任务使用独立评审与 v3 逐项验收。图集按需使用，不参与启动。

## 入口和维护位置

| 对象 | 位置与作用 |
| --- | --- |
| 默认触发 | `~/.codex/AGENTS.md` 的“默认工作方式”条目；目标项目可补充自身有效约定 |
| 用户级技能 | `~/.agents/skills/work-eval`；采用源码链接方式时指向本地维护项目的 `skills/work-eval` |
| 流程源码 | 本项目的 [SKILL.md](../skills/work-eval/SKILL.md)、references 和 scripts；后续优化只维护这一份 |
| 任务记录 | 计划优先遵守目标项目约定，否则启动目录 `.codex/plan/<任务>/`；证据放启动目录 `.codex/verification/` |

默认入口配置并经客户端发现核验后，日常直接提出任务即可，无需输入启动命令。技能目录负责提供规则和脚本，业务工作区负责保存任务记录；读取本项目的通用参考文件，不会把本项目 AGENTS.md、根标记、图集或业务授权带到其他项目。

符号链接让源码修改供后续读取直接使用，不需要重新复制或安装。已加载技能的在途会话仍须刷新必要内容；新会话要核对对应客户端的实际发现结果，不能把一台机器上的 CLI 验证推广为所有宿主都已生效。维护目录移动后需更新链接，并重新验证加载。

## 默认分流

- 纯问答与状态查询：直接回答，不创建验收记录。
- 简单实质任务：执行、核验并保留必要终态证据，无需契约或 score。
- 复杂任务或关键证据冲突：固定必要结果，执行并验证，独立复核，调用 score；未通过且可继续时回修。
- 只读委派：按父任务约定返回结果，不递归建立评审链。

完整规则以 [默认技能](../skills/work-eval/SKILL.md) 为唯一正文；独立评审不可用时如实注明 self，脚本结果最多 provisional，不冒充独立通过。用户的操作授权、测试约定和目标项目规则继续适用。

## 验收脚本与 Stop 的区别

`score` 从安装技能的 `scripts/work_eval.py` 调用，支持维护目录外的任务，报告写到该任务的契约目录。它检查结构、版本、引用和已声明操作，不是业务执行器，也不证明评审者身份或主张语义。

`arm`、`release`、`hook` 仍限制在 agent-workflow 维护项目内，用于明确授权的实验。默认流程没有安装全局 hooks 或角色。项目外 hook 返回空响应，只表示跳过；Stop 最多请求继续一次，不能保证宿主执行或任务完成。扩大自动门禁范围仍需真实宿主事件、项目隔离、退出与恢复验证。

## 验证范围

当前协议回放项数、公开复现命令、版本哈希及真实案例边界见[验证摘要](验证摘要.md)。维护者曾验证本机 CLI 的规则与技能发现、通过符号链接调用 score、版本变化拒绝、项目外门禁隔离，以及独立代理执行简单文档修改。这些私人会话工件不随项目发布，其他使用者应在自己的环境复验。

模型 A/B 尚未运行；不能把协议通过或个别任务成功解释为所有任务可靠，安装默认流程也不等于全局强制门禁。
