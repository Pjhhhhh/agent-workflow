# 固定真实任务检验

T01–T03 的模型对照尚未运行：模型、推理设置、评审方式和预算未选定，评审校准未通过，12 个代理试次尚未启动。审查派生案例有明确输入设计，独立候选源码尚未生成。本页给出可执行设计与启动条件；现有检查结果见[验证摘要](验证摘要.md)。

## 检验目标

比较代理实际完成的必要结果、无依据事实、范围外操作、可继续却早停和人工纠正，同时记录耗时与可取得的用量。每个案例按原任务要求判断：资料不足时如实保留未知可以符合研究任务，缺少必填业务信息的交付仍须保留未完成项。

真实场景、评审校准、固定条件、单项改变与保留集方法参考 [Lance Martin 的 eval 设计方法](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)、[build-eval 指南](https://github.com/anthropics/skills/blob/8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4/skills/claude-api/shared/evals/build-eval.md)和 [hillclimb 指南](https://github.com/anthropics/skills/blob/8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4/skills/claude-api/shared/evals/eval-hillclimb.md)。

## 固定案例

| 案例 | 输入与任务 | 必要结果 | 观察方式 |
| --- | --- | --- | --- |
| T01 文档修改 | 修正文档中的当前计划约定 | 新计划路径相关说明一致，明确既有档案与 .codex 实验记录的归属；修改限于计划路径说明和忽略规则 | 对照冻结输入与结果，按 UTF-8 重读，检查本地链接和实际差异 |
| T02 代码缺陷修复 | 使用证据身份判断存在缺陷的源码快照，修复原要求冒充完成证据的问题 | 正常证据通过；原请求及指向同一文件的别名、符号链接、硬链接不能冒用；保持快照的 CLI 和权限约定 | 实际运行 score，保存输入、退出码、理由及差异，核对各类身份输入和正常证据 |
| T03 资料研究 | 核查指定文章的参考情况，并设计固定真实任务的检验方式 | 来源支持结论；分别核查起始材料中的参考记载与全部相关记录的阅读情况；资料取得情况、实验设计和实测状态清楚 | 独立阅读请求、来源正文与回答，逐项核对主张和实际结果 |

每例固定原始请求或明确标注的派生任务、起始工件、必要验收、允许操作、可观察结果和恢复条件。先确认起始缺陷可复现、任务可解，再在独立试次目录复制起始状态；目标路径可按试次重定位，其他条件保持一致。冻结案例和输入清单在项目根 `.plan/真实任务检验/` 管理。

## 审查案例

R01–R04 从 T02 派生，用于区分真实缺陷、未完成修复、安全反例和无关改动。起始请求位于本地 `.plan/真实任务检验/cases/T02-原请求冒用/prompt.md`；当前身份判断实现见[评分器](../skills/work-eval/scripts/work_eval.py)的 `non_request_file()` 与 `evidence()`。执行前冻结所用源码、派生差异、请求和预期。

| 输入 | 应核对的发现或反证 | 修复与复验范围 |
| --- | --- | --- |
| R01 缺陷输入：`evidence()` 只要求已声明证据存在，必要项仅以原请求作为完成证据 | 请求说明要求，完成须有实际结果证据；直接路径、等价路径、符号链接和硬链接均须检查同一文件身份 | 拒绝冒用并给出理由和下一动作；正常独立证据仍通过，保持快照 CLI、输入和退出码约定 |
| R02 未完成修复：仅以 `p != request_artifact` 排除直接路径，其他逻辑不变 | 核对实际结果；字符串不同但指向同一文件的输入仍可能冒用，同一根因合并记录 | 补足身份判断后重测所有冒用输入和正常证据，读取错误按原约定处理 |
| R03 安全反例：`samefile` 排除请求身份，缺失文件或 `OSError` 返回 False；必要项要求非请求证据且所有引用存在 | 读取调用与保护分支，用实际输入核对；缺少额外字符串比较或手工归一化本身不构成缺陷 | 保留有效保护；实际绕过时附触发证据，验证受影响范围 |
| R04 无关改动：仅调整 R03 中返回谓词上方解释请求用途的注释，保持署名、谓词和调用 | 无行为缺陷时不产生 finding；个人风格建议单列，阻塞项依据必要要求或已确认缺陷 | 该注释改动不改变行为，复用未受影响的验证结果 |

普通 bug 同样按原 CLI 约定记录，包括正常证据被错误拒绝、缺失证据被错误放行和读取错误导致非约定退出。统计有效发现、误报、已解决后的重复发现、复审轮数、人工处置和范围变化。同一未修改代码的零散漏报用于复查首轮覆盖；新回归与重复发现分别统计。

## 执行步骤

1. **确认起始输入。** 保存案例来源、初始工件和必要差异，核对任务与验收可执行。输入包含常规可完成、真实困难及应保留未知的情况。
2. **校准评审。** 使用已知正确、空输出、只声称成功但实际没做的样本；对同一输出重复评审，核对不一致原因。代码检查用于确定性部分，复杂语义由独立模型或人工直接读取请求与工件，完成校准后再用于比较。
3. **固定对照。** 基线为稳定规则，候选只改变一个待测因素。固定必要结果、允许操作、模型、推理设置、工具、权限、输入、环境、预算和用户反馈策略；每个试次从相同起始工件创建新环境。
4. **运行并保存证据。** 保存可取得的完整轨迹、原始输出、最终工件、差异、逐项判断、退出状态、耗时和用量。超时记为未完成；工具或环境故障单独标记，无法取得的费用或用量保留未知。
5. **判断改动效果。** 先比较必要项与具体错误，再比较耗时和成本。证据支持改善时保留候选；评审或环境存在缺陷时先修复实验，更换评审版本后对基线和候选全部重评。

最终工件和实际状态用于判断完成，过程轨迹用于检查早停、越权和判断依据；方法见 [Anthropic agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。

## 规模与结果记录

首轮规模为 3 例 × 2 个规则版本 × 2 次重复，共 12 个代理试次，用于检查环境、评审和改动方向。每个试次可包含多次工具与模型调用，校准、重评和重试分别计入记录。正式规模依据观察波动与需要识别的最小改善确定。

逐试次记录必要项通过、失败或未验证，以及无依据事实、范围外操作、可继续却结束和人工纠正。必要项全部通过且没有实质越权时，才计为完整完成；明确允许的未知按原任务要求判断。

扩大任务集时，优化者只读训练失败，用验证集选择版本，最终用未参与选择的保留集检验。反复用于选版本的集合按验证集处理。

## 启动条件与运行隔离

模型、推理设置、评审方式和预算写入运行记录，评审校准通过后才启动对照。运行环境将候选进程限定到本试次允许的输入、工具和当前产物，隔离评审答案、其他试次、成功交付、评审代码、优化报告及历史记忆。正式执行前预检：允许文件可读，评审及其他试次文件不可读。

计划、案例和冻结清单放在项目根 `.plan/`，日志和状态按启动目录的任务约定保存；独立运行目录按[任务跟踪](agents/issue-tracker.md)定位。真实业务操作沿用原任务授权，公开可运行的协议演示见[示例说明](../examples/README.md)。

## 全局规则的五类实际过程检查

该组检查用于核对规则加载与实际行为。使用正常配置下的原生 Codex 新会话和明确 ID 续接，写入限制在受控夹具。普通问答位于维护项目外；文件任务同时继承项目规则，按相应条件归因。现有样本结果见[验证摘要](验证摘要.md#受控任务样本)。

| 过程 | 输入与操作 | 必要证据 |
| --- | --- | --- |
| 普通问答 | 项目外 read-only 会话回答简单自然问题 | 全局加载片段、回答与工具事件，核对直接表达及额外动作 |
| 只读审查 | 读取有明确输入和约定的受控代码 | 正文、具体触发路径、原生工具日志和夹具未改动 |
| 代码与文档修改 | 获得指定文件授权，使用夹具已有检查入口 | 实际差异与检查输出，核对完整修改、验证和无关文件生成 |
| 用户纠正后继续 | 更新夹具内容并给出有效纠正 | 最新内容保留、受影响项修改及原任务连续性 |
| 途中问题与恢复 | 原任务过程中提问，使用明确会话 ID 续接 | 回答、中间状态、resume 事件与后续完成；强制压缩恢复单独检验 |
