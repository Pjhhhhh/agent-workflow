# 维护与验证

流程、技能、可选角色模板和源码在本项目维护。安装、更新、卸载及相关会话的生效操作见[安装与更新](安装与更新.md)。

## 文件归属

README 提供安装和使用入口；各技能的必需资料放在各自的 `skills/<技能名>/` 内，docs 保存按需阅读的项目说明。`docs/research/` 保存工具比较、本机适用性调研与研究原稿，默认在本地保留；公开已采用结论时，将其整理为正式项目说明。提交前核对待公开的源码、文档、例子和图集，并检查实际 Git 差异。`.plan/` 保存维护计划，`.codex/` 保存本地任务与验收材料；临时产物按全局 AGENTS.md 的统一临时路径约定存放。

任务沿用已有计划、必要日志和交付文件；需要独立保存运行记录时使用启动目录 `.codex/verification/<task_id>/<唯一run_id>/`，保留历史输入和判断。展示真实案例时只公开脱敏结论与验证边界。

## 发布清单自检

维护者在本机准备公开文件时，运行只读检查：

```sh
python3 scripts/verify_release.py --root . --manifest release-files.txt
```

`release-files.txt` 列出本项目待公开的文件，相对清单路径按 `--root` 解析。清单使用 UTF-8，一行一个相对 `--root` 的文件路径，忽略空行和 `#` 开头的整行注释，支持中文及空格路径。脚本只读检查清单文件是否存在、Markdown 本地文件引用是否纳入清单，以及路径是否位于根目录内。输出 JSON 可由调用者保存；退出码 0 表示通过，1 表示清单或引用存在缺陷，2 表示参数或读取错误。

## 重放协议

先进入项目根目录，执行：

```sh
python3 scripts/verify_protocol.py
```

结果包含实际 subprocess 命令、输入、退出码和输出，用于核对协议处理；合成 case 中的 independent 标签属于测试数据。每次运行生成独立目录，保留旧证据。协议变化后同步复核技能与示例，确认说明符合当前行为。

无参数默认运行 `all`。需要单独核对时，传 `--suite score` 检查记录与报告目录隔离，传 `--suite hook` 检查局部门禁及历史早停连续链，传 `--suite installed` 检查任务目录内的独立技能副本；hook 分组包含必要的 score 前置。每组独立保存本轮记录，`--help`、非法组和仅导入脚本均不创建运行目录。

输入字段、检查状态及兼容行为见[记录检查协议](../skills/work-eval/references/record-checking-protocol.md)；命令、前置条件和局部门禁实验见[功能入口](../skills/work-eval/references/cli-reference.md)。

## 更新图

图源 JSON 位于 docs/diagrams/specs/，作者为 Pjh；生成与检查需要本机已安装的 Archify 和 Node。将 `ARCHIFY_CLI` 设置为安装包中 bin/archify.mjs 的绝对路径，在本次任务临时根内准备图形输出目录，再从项目根运行。下例检查图 05，其他图替换对应源文件与文件名。浏览器检查前核对生成器的清理方式；涉及递归永久删除临时目录时，按宿主删除规则先采用已核验的任务隔离移动适配：

```sh
diagram_output=".codex/tmp/<任务标识>/diagram/05-local-evaluation"
mkdir -p "$diagram_output"
node "$ARCHIFY_CLI" validate workflow docs/diagrams/specs/05-local-evaluation.json --quality showcase --json
node "$ARCHIFY_CLI" deliver workflow docs/diagrams/specs/05-local-evaluation.json "$diagram_output/05-local-evaluation.html" --quality showcase --json
node "$ARCHIFY_CLI" check "$diagram_output/05-local-evaluation.html" --require-provenance --json
node "$ARCHIFY_CLI" visual-check "$diagram_output/05-local-evaluation.html" --out-dir "$diagram_output/visual-check" --summary --require-provenance
```

deliver 的显式输出路径将 HTML 与原生 delivery.json 保存在任务临时目录，覆盖图源 `meta.output` 中的正式交付位置。来源核验和浏览器检查读取同目录的原始 HTML 与 delivery.json；检查通过并实际查看图形后，将 HTML 复制到正式路径并核对字节一致。截图与浏览器侧车留在任务临时根，必要验收记录放 `.codex/verification/`。

图形验证包括结构检查、浏览器运行与布局检查，以及实际截图检查。分别保存对应结果，并根据本次浏览器记录和实际截图判断是否符合要求。

## 按失败维护入口

维护验证入口时，按问题所在位置处理：

1. 说明与已核实的当前行为不符时，修订说明及相关入口。
2. 工具无法观察必要结果时，补充工具的观察能力，并用实际对象核验。
3. 产品实际结果不符合要求时，回到任务执行，修复产品并验证原用户路径。

功能变化或出现真实失败后，验证受影响行为，复用未受影响的有效证据。恢复任务时沿用原计划和验收记录；定时维护按用户请求配置。项目验证技能和 Feature Map 的生成、维护入口见[可选接入说明](../skills/work-eval/references/optional-integrations.md#项目验证与性能结论技能pstack-移植)。

## 后续试验

检验工作流的实际效果时，从四类真实任务中选择用户认可的样例，保留输入和环境，记录必要项、遗漏要求、返工、催促及耗时。日常分流见[默认工作流技能](../skills/work-eval/SKILL.md)，运行目录和恢复见[任务跟踪约定](agents/issue-tracker.md)，已有验证结果见[验证摘要](验证摘要.md)。

安装默认技能、配置全局 hooks 和配置角色分别核对授权。接入原生钩子前，单独验证宿主支持的项目范围、事件字段、退出规则和路径写权限；缺少必要证据时继续手动运行。

同一规则在负责该主题的协议或说明中维护，入口文件引用它。单次轨迹与偶发错误保存在任务记录中；多次真实案例支持的经验合并到对应局部说明，写明来源、适用条件及失效条件。方法来源为 [HumanLayer 原始技能](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/build-iterated-agentic-loop/skills/build-iterated-agentic-loop/SKILL.md)。
