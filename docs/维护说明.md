# 维护与验证

流程、技能、可选角色模板和源码在本项目维护。安装、更新、卸载及相关会话的生效操作见[安装与更新](安装与更新.md)。

## 文件归属

README 提供安装和使用入口；各技能的必需资料放在各自的 `skills/<技能名>/` 内，docs 保存项目说明，`docs/research/` 保存工具比较与研究原稿。`.plan/` 保存维护计划，`.codex/` 保存任务与验收材料；临时产物按全局 AGENTS.md 的统一临时路径约定存放。

## 发布清单自检

检查待分发文件时，运行：

```sh
python3 scripts/verify_release.py --root . --manifest release-files.txt
```

`release-files.txt` 列出本项目待公开的文件，相对清单路径按 `--root` 解析。清单使用 UTF-8，一行一个相对 `--root` 的文件路径，忽略空行和 `#` 开头的整行注释，支持中文及空格路径。脚本只读检查清单文件是否存在、Markdown 本地文件引用是否纳入清单，以及路径是否位于根目录内。输出格式为 JSON；退出码 0 表示通过，1 表示清单或引用存在缺陷，2 表示参数或读取错误。

## 重放协议

先进入项目根目录，执行：

```sh
python3 scripts/verify_protocol.py
```

结果包含实际 subprocess 命令、输入、退出码和输出，用于核对协议处理；合成 case 中的 independent 标签属于测试数据。每次运行生成独立目录，保留旧证据。协议变化后同步复核技能与示例，确认说明符合当前行为。

无参数默认运行 `all`。需要单独核对时，传 `--suite score` 检查记录与报告目录隔离，传 `--suite hook` 检查局部门禁及历史早停连续链，传 `--suite installed` 检查任务目录内的独立技能副本；hook 分组包含必要的 score 前置。每组独立保存本轮记录。

输入字段、检查状态及兼容行为见[记录检查协议](../skills/work-eval/references/record-checking-protocol.md)；命令、前置条件和局部门禁实验见[功能入口](../skills/work-eval/references/cli-reference.md)。

## 更新图

图源 JSON 位于 docs/diagrams/specs/，生成与检查使用已安装的 Archify 和 Node。将 `ARCHIFY_CLI` 设置为安装包中 bin/archify.mjs 的绝对路径，在本次任务临时根内准备图形输出目录，再从项目根运行。下例检查图 05，其他图替换对应源文件与文件名。浏览器检查前核对生成器的清理方式；若生成器会递归永久删除临时目录，先按宿主删除规则将清理改为移动本次临时目录，核验后再运行：

```sh
diagram_output=".codex/tmp/<任务标识>/diagram/05-local-evaluation"
mkdir -p "$diagram_output"
node "$ARCHIFY_CLI" finalize workflow docs/diagrams/specs/05-local-evaluation.json "$diagram_output/05-local-evaluation.html" --quality showcase --json
```

`finalize` 完成结构校验、生成、来源检查和实际浏览器检查。显式输出路径将 HTML 与原生交付回执保存在任务临时目录，覆盖图源 `meta.output` 中的正式交付位置；检查通过后，将 HTML 复制到正式路径并核对字节一致。原始回执与浏览器记录保存在任务临时根。需要视觉审阅时，按当前 Archify 技能进行截图与实际查看。

## 按失败维护入口

维护验证入口时，按问题所在位置处理：

1. 说明与已核实的当前行为不符时，修订说明及相关入口。
2. 工具无法观察必要结果时，补充工具的观察能力，并用实际对象核验。
3. 产品实际结果不符合要求时，回到任务执行，修复产品并验证原用户路径。

功能变化或出现真实失败后，验证受影响行为，复用未受影响的有效证据。项目验证技能和 Feature Map 的生成、维护入口见[可选接入说明](../skills/work-eval/references/optional-integrations.md#项目验证与性能结论技能pstack-移植)。
