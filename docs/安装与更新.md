# 安装、更新与退出

安装器需要 Node.js 22.20+，默认安装到当前项目；命令末尾加 `-g` 表示用户级安装，在交互中选择目标客户端。要求与参数见安装器的[README](https://github.com/vercel-labs/skills/blob/1a1d387ed4286e59aa43a2696cf02b3590061c91/README.md)和[命令说明](https://github.com/vercel-labs/skills/blob/1a1d387ed4286e59aa43a2696cf02b3590061c91/docs/commands.md)。

## 安装技能入口

`work-eval` 用于执行任务、核验结果和恢复未完成工作：

```sh
npx skills add Pjhhhhh/agent-workflow --skill work-eval
```

安装后，在支持 Agent Skills 的宿主中调用 `work-eval`。希望默认用于实质任务时，在自己的代理规则中添加按任务读取该技能的入口，沿用现有通用行为、权限和项目约定。

## 安装 doc-maintenance

`doc-maintenance` 用于文档任务的编写与处理，需单独安装：

```sh
npx skills add Pjhhhhh/agent-workflow --skill doc-maintenance
```

安装后，在文档任务中调用 `doc-maintenance`，按请求处理目标文档。它根据已有宿主或项目配置读取适用文档规范；未配置专项规范时，沿原请求和既有项目约定执行。

## 可选安装方式

也可以把所需的 `skills/work-eval` 或 `skills/doc-maintenance` 整个目录复制到宿主技能目录，保留其中的参考资料及附带脚本。`work-eval` 的脚本需要 Python 3.9+，只使用标准库；`doc-maintenance` 由技能正文与参考文档组成。

维护源码时可使用符号链接。以下为支持 `~/.agents/skills` 的宿主提供用户级 `work-eval` 示例；安装 `doc-maintenance` 时，将其中的 `work-eval` 替换为 `doc-maintenance`。在完整项目根目录执行，已有同名目录或链接时先核对原安装，不覆盖：

```sh
workflow_source="$(pwd -P)"
if [ ! -f "$workflow_source/skills/work-eval/SKILL.md" ]; then
  echo '请先进入完整项目根目录'
elif [ -e "$HOME/.agents/skills/work-eval" ] || [ -L "$HOME/.agents/skills/work-eval" ]; then
  echo '已有 work-eval，请核对当前链接或目录，不覆盖'
else
  mkdir -p "$HOME/.agents/skills"
  ln -s "$workflow_source/skills/work-eval" "$HOME/.agents/skills/work-eval"
fi
```

## 安装后的最小验收

1. 在目标宿主中选择已安装的技能，确认会话实际读取安装目录中的 `SKILL.md` 及所需参考；符号链接先解析真实位置。
2. `work-eval` 使用一个范围明确的小任务，核对实际结果、允许的差异和验证结论；`doc-maintenance` 使用一段新说明、指定段落修订或只读审阅，核对它是否读取适用规范，并检查内容用途与请求范围。
3. 确认任务记录留在业务工作区。

## 先试运行

需要检查 `work-eval` 附带脚本时，按[示例说明](../examples/README.md)和[功能入口](../skills/work-eval/references/cli-reference.md)操作，核对各命令的预期结果。

## 更新技能

先核对当前技能的真实安装位置和来源，备份本地定制及未提交差异，再选择对应更新方式：

- 源码符号链接：确认链接指向预期源码目录，在源码中核对版本和差异后更新；源码目录移动时，同步更新链接目标。
- 复制安装：以完整技能目录为单位更新，保留所含的脚本和参考资料；先比较本地修改，再合并获授权的更新及自管内容。
- 安装器管理：按安装器当前说明，选择目标客户端、安装范围和指定技能进行更新。

完成后核对实际入口、完整目录、版本或来源及本地引用，按下表确定本次需要的生效操作。

## 更新后怎样生效

| 修改对象 | 生效条件与必要操作 |
| --- | --- |
| Python 脚本 | 下一次新进程调用使用新版；已运行的进程及旧报告保持原版本 |
| 技能正文、流程参考 | 让相关会话实际重读更新内容，确认当前任务采用的版本 |
| AGENTS.md | 当前任务可显式重读；重启 Codex 可重新构建启动指令链 |
| config.toml、技能启停或运行组件 | 重启相关组件并核对当前生效配置 |

需要用户执行生效操作时，告知具体操作与原因。重启前保存当前计划、未完成项和证据，恢复后核对真实文件，沿用当前任务、授权及仍有效的证据继续。官方说明：[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[技能](https://learn.chatgpt.com/docs/build-skills)。

## 退出使用

退出某个技能时，先从自己的代理规则中移除对应入口，保留其他约定与用户级文档规范。按实际安装范围定位 `work-eval` 或 `doc-maintenance` 的目录或链接；源码符号链接只移除链接，不删除源码与任务证据，真实目录按所用安装方式和已有授权处理。随后让客户端刷新，并确认技能发现与规则入口已更新。
