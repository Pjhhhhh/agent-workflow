# 安装、更新与退出

安装器需要 Node.js 22.20+，默认安装到当前项目；命令末尾加 `-g` 表示用户级安装，在交互中选择目标客户端。要求与参数见安装器的[README](https://github.com/vercel-labs/skills/blob/1a1d387ed4286e59aa43a2696cf02b3590061c91/README.md)和[命令说明](https://github.com/vercel-labs/skills/blob/1a1d387ed4286e59aa43a2696cf02b3590061c91/docs/commands.md)。

## 安装 work-eval

`work-eval` 用于执行任务、核验结果和恢复未完成工作：

```sh
npx skills add Pjhhhhh/skills --skill work-eval
```

安装后，按[调用技能](#调用技能)开始一个任务；若要默认用于实质任务，再配置[按任务读取入口](#按任务默认使用)。

## 安装 doc-maintenance

`doc-maintenance` 用于文档任务的编写与处理：

```sh
npx skills add Pjhhhhh/skills --skill doc-maintenance
```

安装后，按[调用技能](#调用技能)提交文档任务。技能会读取宿主或项目配置的文档规范；未配置专项规范时，按任务要求和项目约定处理文档。

## 调用技能

在 Codex CLI 或 IDE 扩展中，可以输入 `/skills` 或 `$` 选择已安装的技能，也可以在请求中用 `$技能名` 显式调用。以下示例针对当前项目中的 `README.md`；使用时按实际目标文件和允许的修改调整：

```text
$work-eval 检查 README.md 中的相对链接，修复已确认的失效链接，并核对链接目标。
$doc-maintenance 只读审阅 README.md，检查新读者能否理解用途并开始使用，返回问题位置、依据和影响。
```

Codex 也会按技能的 `description` 判断是否适用；显式选择可以确认本次使用哪项技能。初始发现只读取技能元数据，选用后才读取完整 `SKILL.md`，调用方式见 [Codex 技能说明](https://learn.chatgpt.com/docs/build-skills)。其他客户端使用各自的技能选择入口。

## 按任务默认使用

希望某项技能默认用于相应任务时，在客户端实际加载的代理规则中添加按需读取入口。先确认已安装技能的 `SKILL.md` 路径，只添加需要的入口。以下以支持 `~/.agents/skills` 的安装为例，路径需换成实际安装位置：

```markdown
- 实质任务读取 `~/.agents/skills/work-eval/SKILL.md`，按任务职责执行与核验。
- 文档任务读取 `~/.agents/skills/doc-maintenance/SKILL.md`，按适用规范编写、修改或审阅。
```

安装技能和配置代理规则是两个操作。修改规则后，按[生效说明](#更新后怎样生效)让相关会话读取入口，再完成下面的最小验收。

## 工程与验证方法怎样接入

`work-eval` 包含 [Matt Pocock 工程技能接入规则](../skills/work-eval/references/matt-pocock.md)与 [pstack 验证接入规则](../skills/work-eval/references/pstack.md)，按任务需要选择诊断、任务安排、实施、审查、应用验证、性能测量或变更影响方法。

第三方技能正文由使用者另行安装。触发相应方法时，先核对目标宿主实际提供的技能与可读取版本；已有项目验证技能优先复用。缺少某项技能时，继续已有工具能完成的工作，并保留受影响的必要项及恢复条件。安装或配置第三方技能按当前授权执行。

## 可选安装方式

也可以把所需的 `skills/work-eval` 或 `skills/doc-maintenance` 整个目录复制到宿主技能目录，保留其中的参考资料及附带脚本。`work-eval` 的脚本需要 Python 3.9+，只使用标准库；`doc-maintenance` 由技能正文与参考文档组成。

维护源码时可使用符号链接。以下为支持 `~/.agents/skills` 的宿主提供用户级 `work-eval` 示例；安装 `doc-maintenance` 时，将其中的 `work-eval` 替换为 `doc-maintenance`。在完整项目根目录执行，已有同名目录或链接时先核对原安装，不覆盖：

```sh
workflow_source="$(pwd -P)"
if [ ! -f "$workflow_source/skills/work-eval/SKILL.md" ]; then
  echo '请先进入完整项目根目录'
elif [ -e "$HOME/.agents/skills/work-eval" ] || [ -L "$HOME/.agents/skills/work-eval" ]; then
  echo '已有 work-eval，请核对当前链接或目录，不覆盖'
else
  mkdir -p "$HOME/.agents/skills"
  ln -s "$workflow_source/skills/work-eval" "$HOME/.agents/skills/work-eval"
fi
```

## 安装后的最小验收

1. 按[调用技能](#调用技能)在目标客户端提交任务，确认会话实际读取安装目录中的 `SKILL.md` 及所需参考；符号链接先解析真实位置。
2. `work-eval` 使用一个范围明确的小任务，核对实际结果、允许的差异和验证结论；需要工程或专项验证方法时，再核对所选第三方技能是否实际读取。`doc-maintenance` 使用一段新说明、指定段落修订或只读审阅，核对它是否读取适用规范，并检查必要信息、内容组织与请求范围。只读审阅应返回有依据的审阅结论，有问题时注明位置与影响。
3. 如任务产生记录，确认记录留在业务工作区。

## 检查 work-eval 脚本

需要检查 `work-eval` 附带脚本时，按[示例说明](../examples/README.md)和[功能入口](../skills/work-eval/references/cli-reference.md)操作，核对各命令的预期结果。

## 更新技能

先核对当前技能的真实安装位置和来源，备份本地定制及未提交差异，再选择对应更新方式：

- 源码符号链接：确认链接指向预期源码目录，在源码中核对版本和差异后更新；源码目录移动时，同步更新链接目标。
- 复制安装：以完整技能目录为单位更新，保留所含的脚本和参考资料；先比较本地修改，再合并获授权的更新及自管内容。
- 安装器管理：按安装器当前说明，选择目标客户端、安装范围和指定技能进行更新。

完成后核对实际入口、完整目录、版本或来源及本地引用，按下表确定本次需要的生效操作。

## 更新后怎样生效

| 修改对象 | 生效条件与必要操作 |
| --- | --- |
| Python 脚本 | 下一次新进程调用使用新版；已运行的进程及旧报告保持原版本 |
| 技能正文、流程参考 | 让相关会话实际重读更新内容，确认当前任务采用的版本；Codex 可自动发现技能变化，若未出现更新，再重启 |
| AGENTS.md | 当前任务可显式重读；重启 Codex 可重新构建启动指令链 |
| Codex 的 config.toml（含技能启停） | 修改后重启 Codex，核对当前生效配置 |

需要重启时，先保存未完成的工作及其记录；重启后核对当前技能入口和配置，继续原任务。Codex 对应说明：[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[技能](https://learn.chatgpt.com/docs/build-skills)。

## 退出使用

退出某个技能时，先从自己的代理规则中移除对应入口，保留其他约定与用户级文档规范。按实际安装范围定位 `work-eval` 或 `doc-maintenance` 的目录或链接；源码符号链接只移除链接，不删除源码与任务证据，真实目录按所用安装方式和已有授权处理。随后让客户端刷新，并确认技能发现与规则入口已更新。
