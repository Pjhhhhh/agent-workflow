# 任务跟踪：本地 Markdown

本项目的新规格与计划统一放在**项目根目录**的 `.plan/`。项目根由 `.agent-workflow-root` 标记；从子目录启动或后续 cd 均不改变计划归属。实验输入、状态、日志和验收报告属于本次启动目录的 `.codex/`，在计划中记录绝对路径。旧 `.plan/` 或 `.codex/plan/` 记录保留原处，不自动搬迁。

恢复时先读用户明确给出的计划路径，其次读取当前任务已记录的原计划绝对路径；没有指针时，在项目根 `.plan/` 按用户目标查找，必要时再查已知历史位置。核对原 task_id、有效要求与纠正、授权、未完成项、证据版本和下一动作；同一任务沿用原计划及 task_id。只有多个候选无法唯一对应时才澄清，不把其他会话的任务或授权带入。

每次验收使用启动目录 `.codex/verification/<task_id>/<唯一run_id>/`，保留旧轮记录；计划指向当前轮的绝对路径。不同任务使用独立目录，同一计划由一个主代理协调写入，子代理返回结果给父代理汇总。该约定不提供自动加锁或跨会话调度。

## 文件约定

- 每个功能使用独立目录：`.plan/<功能标识>/`。
- 规格文件：`.plan/<功能标识>/spec.md`。
- 实施任务每项一个文件：`.plan/<功能标识>/issues/<NN>-<任务标识>.md`，从 `01` 编号。
- 分诊状态写在任务文件顶部附近的 `Status:` 行；标签含义见 `triage-labels.md`。
- 评论与讨论追加到文件末尾的 `## Comments` 下。

## 技能操作

技能要求“发布到任务跟踪器”时，在对应 `.plan/<功能标识>/` 下创建文件，按需创建目录。

技能要求“读取相关任务”时，读取用户提供的路径；仅提供编号时，在相关功能的 issues 目录内定位。编号不唯一时确认目标。

本约定只定义任务文件的位置；Git 写入、安装和外部发布仍遵循当前授权。

## Wayfinder 探索任务

`/wayfinder` 使用一份探索地图和每项一个的子任务文件：

- 地图：`.plan/<探索标识>/map.md`，记录 Notes、Decisions-so-far 与 Fog。
- 子任务：`.plan/<探索标识>/issues/<NN>-<任务标识>.md`，从 `01` 编号，正文写明待解决的问题。
- 类型：顶部附近的 `Type:` 行使用 `research`、`prototype`、`grilling` 或 `task`。
- 探索状态：`Status: open`、`Status: claimed` 或 `Status: resolved`；此处是探索生命周期，分诊标签按前述映射处理。
- 依赖：`Blocked by: NN, NN`；所有被依赖任务均为 `resolved` 后，任务才解除阻塞。

选择任务时，扫描 issues 目录中状态为 open、依赖已解决的任务，按编号选择第一项。
开始工作前保存 `Status: claimed`。
解决后将答案追加到 `## Answer`，保存 `Status: resolved`，再将结论摘要与子任务链接追加到地图的 Decisions-so-far。
