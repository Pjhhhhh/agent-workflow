# 领域文档

本项目采用 single-context 布局：领域词汇位于根目录 `GLOSSARY.md`，架构决策位于 `docs/adr/`。

## 阅读规则

探索领域之前，读取根目录 `GLOSSARY.md`，以及 `docs/adr/` 下与当前任务相关的 ADR。

这些文件尚不存在时直接继续，不因缺少文件而预先创建或要求补齐。由 `/domain-modeling` 在术语或决策实际确定后按需创建。

若以后根目录出现 `GLOSSARY-MAP.md`，按该地图读取与当前主题相关的 `GLOSSARY.md`，并检查对应 `src/<上下文>/docs/adr/` 的决策。

## 文件布局

- `GLOSSARY.md`：本项目统一的领域概念与术语。
- `docs/adr/`：架构决策记录，采用编号文件，例如 `0001-决策主题.md`。

## 术语与决策

在任务标题、改进提案、假设和测试名称中，使用 `GLOSSARY.md` 定义的术语，避免换成词汇表明确排除的同义表达。
遇到尚未定义的概念时，先判断是否属于项目已有用语；确有缺口时，记录为 `/domain-modeling` 的待澄清项。

提案与现有 ADR 冲突时，明确指出 ADR 编号、冲突内容与重新讨论的理由，再按当前授权处理。
