# Matt Pocock 与 Lauren／Poteto 的流程参考

读取日期：2026-09-30。本项目沿用五阶段流程，完善实际入口、验证证据、回修与恢复。Matt Pocock 的材料可用于对齐需求、按可验证行为切分任务，以及分别检查编码规范与任务规格；Lauren 的 pstack 可用于维护重复调用的验证工具、功能入口索引、证据核查和中断续接。本文说明这些方法在本项目的用途，未比较模型效果。[Matt 的开发阶段文章](https://www.aihero.dev/my-7-phases-of-ai-development)、[Lauren 的 pstack Part 1](https://x.com/poteto/article/2094457600259842065)

## 当前采用的五项做法

| 参考方法 | 在本项目怎样落地 | 适用边界 |
|---|---|---|
| Feature Map 与可重复调用的验证工具 | 新增 [验收功能入口](../skills/work-eval/references/features.md)，记录现有CLI、前置条件、真实输出和副作用；复杂产品再按需记用户入口、复现动作与终态证明 | 沿用已有工具和验收描述，不为日常任务强制建完整地图，也不自动获得启动、安装或外部操作权限 |
| 根据证据区分事实、推断与未知 | 沿用v3的三种主张分类；必要未知记录精确查证对象、版本、冲突和缺口，不猜作者动机、不顺着提问预设结论 | 脚本核对来源定位，语义及记录完整性仍由独立评审检查 |
| 评审与驳回都举证 | 发现关联原话、验收ID、具体触发／缺失观察、证据和动作；误判用反证回评，允许无实质发现 | 以必要未完成项和已证实错误决定回修，不无限追逐每轮新增的主观建议 |
| 恢复引用原工件并复核当前状态 | 接回原task_id、有效请求、未完成项及下一动作；检查失效或变化证据，在局部实验中显式arm当前session／turn | 不复制第二套规格，不把旧通过套在新文件上，也没有自动跨轮关联器 |
| 按可独立证明的行为闭环改进 | 增加历史早停的CLI组合回放，覆盖漏列、分步回修、旧评审失效、新轮恢复与全必要项通过 | 仅证明合成协议；不能称R006真实业务已修好，或AI已不再编造／早停 |

## 维护与后续验证

功能变化或实际任务失败时，先判断是说明过期、工具无法观察，还是产品本身出错，再修对应对象。入口索引应反映约定功能，工具仍需检查产品失败。优先复用现有 CLI、API 和浏览器能力；确有重复需求且现有观察不可靠时，再补必要工具。[维护验证技能](https://github.com/cursor/plugins/blob/fae2c6ed95821bd85f614a73e4842e13229fa5e5/pstack/skills/maintain-verification-skill/SKILL.md)、[Build the Lever](https://github.com/cursor/plugins/blob/fae2c6ed95821bd85f614a73e4842e13229fa5e5/pstack/skills/principle-build-the-lever/SKILL.md)

文章中的每月2000个PR、100—1000倍提升是作者自述，不能替代本项目数据。要判断规则是否降低编造或早停，仍需同一真实任务、固定要求、独立评审与完整运行轨迹，比较漏项、无依据结论、范围外操作、返工和成本。云代理、自动每日routine、Git写入与全局插件接入各自受当前授权约束，参考这些方法不代表已执行这些操作。[pstack Part 1](https://x.com/poteto/article/2094457600259842065)

## pstack 与 HumanLayer 的方法

所核对的 [pstack 仓库](https://github.com/cursor/plugins/tree/main/pstack)就是上文核对的 Lauren 原版，固定提交与版本相同。新增核对的 [HumanLayer skills](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/README.md)在该版本有六个插件入口，具体用途应按仓库文件判断；不能把 HumanLayer 其他仓库中的研究、规划、实施模板全部归到这里。本文采用实际方法，不依赖未经核实的个人履历作背书。

| 可采用的方法 | 本项目的具体做法 | 当前状态 |
|---|---|---|
| pstack 的实际控制入口与证据核查 | 沿用已有 CLI 功能索引，按任务记录终态、输入、差异和复现方式 | 已有，当前继续使用 |
| HumanLayer 的测量、选择动作、执行分工 | 终态证据与评审发现缺口，主代理选下一动作并执行，再核对受影响项 | 已写入工作流程；没有新增自动执行引擎 |
| 具体条件下读取专项资料 | 沿用现有 AGENTS 的文档入口，恢复摘要保留来源、版本、授权和未完成项 | 已有；没有批量引入 XML 标签 |
| 单一规则来源与稳定反馈 | 入口引用相关协议；单次日志留在任务记录，重复案例证实的经验再合并到对应说明 | 已写入维护说明；没有写入长期记忆 |
| 最小视图 | 按当前问题选文字、表格或图，避免把每项任务都变成绘图工作 | README 与工作流程已修正 |

一手依据：[design-control-loop](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/design-control-loop/skills/design-control-loop/SKILL.md)、[具体触发条件](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/improve-claude-md/skills/improve-claude-md/SKILL.md)、[单一规则来源与反馈](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/build-iterated-agentic-loop/skills/build-iterated-agentic-loop/SKILL.md)、[最小视图](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/show-me/skills/show-me/SKILL.md)。这些方法已用于本地说明与任务准备；减少编造、早停或返工的效果尚未通过模型对照验证。

完成一个小单元后仍须接回原任务，其他必要项可推进时继续。上游的固定十路 swarm、云端定时任务、全套测试、宽权限 runner 及提交／推送／PR 流程另有运行条件，本项目没有因参考这些材料而启用它们。

## HumanLayer 的上下文工程与历史 RPI 模板

进一步参考 [Advanced Context Engineering for Coding Agents](https://www.humanlayer.dev/blog/advanced-context-engineering)（2025-08-29）及 [12-Factor Agents](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/README.md)。文章把研究、计划、实现分别整理，重视关键判断的提前审阅，也说明研究可以省略或多轮进行。它的 40%—60% 上下文利用率和案例产量是作者实践，不作为本项目固定阈值或成功证据。

本项目采用两处说明：研究进入计划前，核对决定修改的依据、原目标和验证终态；压缩与恢复时，保留有效要求、未完成项、当前失败和原件路径。摘要用于定位原记录，不能替代当前工件或把推断升级成事实。主代理继续负责所有必要项；按需要使用聚焦调查，局部小项通过后回到总任务。

2025 年文章中的复杂任务实践依赖人的研究和计划审阅。本项目在既有授权内继续技术核对，适用规则要求独立评审时由评审者检查，缺真实信息、业务选择或权限才询问用户。这是为本项目做的适配，效果仍需实际对照，不声称原作者已经验证这套替代分工。

三个以下划线命名的命令属于主仓库的旧文件：[research_codebase](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/research_codebase.md)、[create_plan](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/create_plan.md)、[implement_plan](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/implement_plan.md)。2026-09-30 核查的固定提交为 `99abe673498cf8bdcd5f989aebe9406a27185b3b`；其 [README](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/README.md)明确旧代码基本弃用、重建版本迁往 humanlayer.com。这些文件只作为历史方法模板，不当成当前受维护的安装入口，也不归到六插件的 skills 仓库中。

当前新站使用 `/rpi:*` 并允许按任务选择阶段和短路径。其中 RPI 与 PRD-Oriented 两个当前任务选项从结构概要进入实现，跳过详细计划，旧详细计划路径仍保留。这里只按 2026-09-30 读取范围说明区别，不把未标版本的新产品文档与旧仓库提交混为一套。它也支持本项目的取舍：复杂任务按风险查证和规划，简单任务不强制套完整三阶段。[阶段说明](https://docs.humanlayer.com/explanation/workflow-phases)、[详细计划与旧 RPI](https://docs.humanlayer.com/reference/skills-workflows)
