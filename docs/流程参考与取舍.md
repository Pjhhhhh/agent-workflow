# 流程参考与取舍

读取日期：2026-09-30。以下记录本项目对流程方法的采用决定。Matt Pocock 的材料用于确认需求、按可验证行为划分任务，以及分别检查编码规范与任务规格；Lauren 的 pstack 用于维护重复调用的验证工具、功能入口索引、证据核查和中断续接。来源为 [Matt 的开发阶段文章](https://www.aihero.dev/my-7-phases-of-ai-development)和 [Lauren 的 pstack Part 1](https://x.com/poteto/article/2094457600259842065)。

## 当前采用的五项做法

| 参考方法 | 本项目的采用方式 | 使用条件 |
|---|---|---|
| Feature Map 与可重复调用的验证工具 | 用[功能入口](../skills/work-eval/references/cli-reference.md)记录现有 CLI、前置条件、真实输出和副作用；复杂产品按需记录用户入口、复现动作与终态证据 | 沿用已有工具和验收说明；启动、安装及外部操作按当前授权执行 |
| 根据证据区分事实、推断与未知 | 按三种主张分类记录结论；必要未知写明查证对象、版本、冲突和缺口，依据直接来源判断 | 脚本核对来源定位，评审者核查语义及记录完整性 |
| 评审与驳回都举证 | 为发现附上原话、验收 ID、具体触发条件或缺失观察、证据和动作；误判依据反证重新评审，核查后可报告没有实质发现 | 必要未完成项和已证实错误进入修复 |
| 恢复时引用原工件并复核当前状态 | 接回原 task_id、有效请求、未完成项及下一动作；局部门禁实验中显式 arm 当前 session／turn | 核对变化或失效的证据，复用仍有效的结果 |
| 按可独立验证的行为改进 | 用历史早停的 CLI 组合回放，覆盖遗漏要求、分步修复、旧评审失效、新轮恢复及全部必要项通过 | 回放检验合成协议处理；业务结果按真实任务验收 |

## pstack 与 HumanLayer 的方法

采用的 [pstack 仓库](https://github.com/cursor/plugins/tree/main/pstack)为 Lauren 原版，固定提交与版本见上文。[HumanLayer skills](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/README.md)在所核对版本有六个插件入口，具体方法及本项目采用方式如下。

| 方法 | 本项目的采用方式 |
|---|---|
| pstack 的实际控制入口与证据核查 | 沿用已有 CLI 功能索引，按任务记录终态、输入、差异和复现方式 |
| HumanLayer 的测量、选择动作、执行分工 | 根据终态证据和评审结果查找缺口，主代理选择下一动作并执行，再核对受影响项 |
| 具体条件下读取专项资料 | 沿用现有 AGENTS 的文档入口，恢复摘要保留来源、版本、授权和未完成项 |
| 单一规则来源与稳定反馈 | 入口引用相关协议；单次日志保存在任务记录中，重复案例证实的经验合并到对应说明 |
| 选择合适的呈现方式 | 按当前问题选择文字、表格或图 |

一手依据：[design-control-loop](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/design-control-loop/skills/design-control-loop/SKILL.md)、[具体触发条件](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/improve-claude-md/skills/improve-claude-md/SKILL.md)、[单一规则来源与反馈](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/build-iterated-agentic-loop/skills/build-iterated-agentic-loop/SKILL.md)、[呈现方式](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/show-me/skills/show-me/SKILL.md)。

## HumanLayer 的上下文工程与历史 RPI 模板

进一步参考 [Advanced Context Engineering for Coding Agents](https://www.humanlayer.dev/blog/advanced-context-engineering)（2025-08-29）及 [12-Factor Agents](https://github.com/humanlayer/12-factor-agents/blob/d20c728368bf9c189d6d7aab704744decb6ec0cc/README.md)。文章将研究、计划和实现分别整理，提前审阅关键判断，并按任务选择省略研究或开展多轮研究。

本项目采用两项做法：研究进入计划前，核对决定修改的依据、原目标和验证终态；压缩与恢复时，保留有效要求、未完成项、当前失败和原件路径。摘要定位原记录，并保留事实与推断的区别；恢复时直接核对当前工件。主代理负责全部必要项，按需要安排聚焦调查，局部小项通过后继续总任务。

2025 年文章由人审阅复杂任务的研究和计划。本项目由执行者在既有授权内继续技术核对，适用规则要求独立评审时由评审者检查；缺少真实信息、业务选择或权限时，询问用户。

历史方法模板来自主仓库的三个命令文件：[research_codebase](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/research_codebase.md)、[create_plan](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/create_plan.md)、[implement_plan](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/.claude/commands/implement_plan.md)。2026-09-30 核查的固定提交为 `99abe673498cf8bdcd5f989aebe9406a27185b3b`；其 [README](https://github.com/humanlayer/humanlayer/blob/99abe673498cf8bdcd5f989aebe9406a27185b3b/README.md)当时说明旧代码基本弃用，重建版本迁往 humanlayer.com。

2026-09-30 读取的新站使用 `/rpi:*`，允许按任务选择阶段和短路径。其中 RPI 与 PRD-Oriented 从结构概要进入实现，详细计划路径仍可选择。本项目据此按任务风险选择查证和规划程度。来源为[阶段说明](https://docs.humanlayer.com/explanation/workflow-phases)和[详细计划与旧 RPI](https://docs.humanlayer.com/reference/skills-workflows)。
