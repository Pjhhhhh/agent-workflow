# 流程参考与取舍

工程方法与验证方法围绕同一任务使用。Matt Pocock 技能帮助确定问题、组织实施并审查代码，pstack 方法帮助操作实际应用、取得终态证据并维护验证入口；work-eval 负责完整目标、权限、验收与恢复。

## 工程推进

按[Matt Pocock 接入规则](../skills/work-eval/references/matt-pocock.md)选择当前可读取的技能：故障使用 `diagnosing-bugs`，跨轮实施任务使用 `to-tickets`，明确规格实施使用 `implement`，规范与规格审查使用 `code-review`，路线选择使用 `ask-matt`。项目测试策略和 Git 操作权限继续有效。

规格、任务与验收保留对应关系，使实施者和评审者能够回到有效需求。用户纠正只替换与之冲突的决定，其余已确认行为继续有效。按可验证行为划分任务的方法见 [Matt 的任务切分](https://github.com/mattpocock/skills/blob/d81f3a183412e71a5b1e84ca21bc1a35eea03a60/skills/engineering/to-tickets/SKILL.md)；分别检查规范和规格的方法见 [Matt 的代码评审说明](https://www.aihero.dev/skills-code-review)。

## 实际验证与验证入口

按[pstack 接入规则](../skills/work-eval/references/pstack.md)，优先复用已有 `verify-<app>` 和交互工具，观察用户路径的实际结果。有重复验证需求且缺少可靠入口时，使用 `create-verification-skill` 建立可执行步骤和 Feature Map；已有入口随应用变化而失效时，使用 `maintain-verification-skill` 核对映射功能的源码与真实交互。方法依据见[生成验证技能](https://github.com/cursor/plugins/blob/fae2c6ed95821bd85f614a73e4842e13229fa5e5/pstack/skills/create-verification-skill/SKILL.md)和[维护验证技能](https://github.com/cursor/plugins/blob/fae2c6ed95821bd85f614a73e4842e13229fa5e5/pstack/skills/maintain-verification-skill/SKILL.md)。

报告性能数字或据此选择方案时，使用 `benchmark-checklist` 核对计时、错误和输出正确性；安全判断需要调查局部差异以外的影响时，使用 `blast-radius`；同类已证实错误反复出现时，使用 `correct` 建立能检出真实错误的约束。操作、安装和清理按当前授权执行。

## 证据判断与评审

结论区分事实、推断与未知，来源正文必须支持对应主张。评审发现包含具体触发条件、依据、影响与下一动作；反证用于修正误判，必要未完成项继续处理。证据判断参考 [pstack epistemics](https://github.com/cursor/plugins/blob/fae2c6ed95821bd85f614a73e4842e13229fa5e5/pstack/skills/why/references/epistemics.md)。

日常任务直接核验工件和行为。显式选用记录检查 CLI 时，[功能入口](../skills/work-eval/references/cli-reference.md)提供命令、前置条件和输出说明，脚本检查已声明记录及引文定位，评审者负责语义和完整性。结果范围见[验证摘要](验证摘要.md)。

## 任务恢复与资料读取

恢复时沿用原计划、有效要求、未完成项、当前失败和原件路径，直接核对当前工件，复用未受影响的证据。摘要保留事实与推断的区别，并能定位原记录。方法参考 [pstack 恢复路径](https://github.com/cursor/plugins/blob/fae2c6ed95821bd85f614a73e4842e13229fa5e5/pstack/skills/poteto-mode/playbooks/session-pickup.md)与 [HumanLayer 上下文工程](https://www.humanlayer.dev/blog/advanced-context-engineering)。局部 Stop 实验的重新登记条件见[功能入口](../skills/work-eval/references/cli-reference.md#恢复同一任务)。

专项资料按任务的具体条件读取，规则集中维护在负责该主题的位置，入口保留必要摘要与链接。根据实际终态选择下一动作，再验证受影响项。相关方法见 [HumanLayer 具体触发条件](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/improve-claude-md/skills/improve-claude-md/SKILL.md)、[单一规则来源](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/build-iterated-agentic-loop/skills/build-iterated-agentic-loop/SKILL.md)与[控制循环设计](https://github.com/humanlayer/skills/blob/ca7c8088db69e315a8b2deea43820270457f8f3c/plugins/design-control-loop/skills/design-control-loop/SKILL.md)。

## 维护与效果检验

说明、观察工具和产品分别按问题所属位置处理，入口见[按失败维护](维护说明.md#按失败维护入口)。协议回放检查确定性记录处理；规则是否改善真实任务完成情况，按[真实任务检验](真实任务检验.md)的固定条件比较。
