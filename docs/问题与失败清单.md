# 问题与失败清单

## 未验证项误触发版本核对（2026-10-10，修改前登记）

一次真实任务的现场必要项尚未验证，契约、工件和评审版本并无已知变化，评分器却因任意unknown追加binding动作，造成无关工件核对。未验证状态本身应保留；问题在下一动作误把证据或现场缺口当作版本缺口。

- 纯现场未验证、主张未知、真实性或范围缺证据及旧协议缺口，保留各自下一动作，不自动追加binding。
- 契约、工件或评审版本不一致，以及声明工件缺失或不是文件，仍需binding；双方哈希同为null也不能漏掉缺失工件。
- 混合缺口保留具体动作与binding，已有判断动作不覆盖、不重复；fail、partial、provisional、pass及权限边界保持原义。

修改前扩展现有真实CLI回放复现误提示，修复后重放全部边界；回放只核验本地协议，不代表现场已恢复。

## 代理文档质量与工具规则漂移（2026-10-09，修改前登记）

共享技能和使用入口仍写绘图“选一种”，与互补工具按需组合存在歧义。代理规则改写的旧核验关注文件安装和加载，却漏查渐进披露与重复规则的语义质量；原有流程没有把专项技能的必要要求明确转为判据，评审也可能沿作者契约的缩窄范围判断完成。

- 工具规则分散维护：选用与协作原则集中在共享技能，入口引用它；具体工具路由留给当前任务和有效项目规则。
- 专项技能已加载但要求未落实：从原目标与专项质量要求分别提取可核验判据，核对实际内容与终态；安装、加载、生成或脚本成功只证明对应环节。
- 作者契约漏项仍被放行：评审者先从原请求、有效纠正和专项必要要求列出应达结果，再与作者契约比对，发现漏项后补齐并回修。

本次修改执行与核对说明，不新增协议字段或测试表单；现有黑盒回放验证协议兼容，语义质量另外核对。规则保存和回放通过均不能证明在途会话已采用新版，或后续模型行为已稳定改善。

## 同一文件内的额外改动（2026-10-05）

真实模板填写任务的旧交付改了工作表、栏目和公式，旧独立评审仍通过。具体原话、旧版本工件与差异留在私人任务证据；后续回修仍在执行，不能将旧错误当作新版本验收结果。

- 编辑与新建分流：已有文件默认保护格式、结构和公式，简单任务也适用；参考资料不自动授权套用样式。
- 固定必要项：原件未改、输出格式保持、可读可编辑分开验收；保留格式不依赖用户重复逐项强调。
- 同文件差异：write目标匹配只证明文件级声明一致，内容、结构、样式及额外交付仍需独立核对。
- 局部适配：依既有授权处理换行、行高等例外，核验受影响部分，不把局部授权扩成整体改版。

本次修复执行与评审说明，不改评分器或扩展协议字段。用冻结的真实原件和旧交付核对上述缺口，规则检查不代表运行中的会话已重读，也不证明后续模型行为稳定。

## 独立技能安装（2026-10-05，修改前登记）

- 单独复制work-eval后，不应依赖仓库外层docs才能读完必需规则；检查所有技能内相对引用仍可读取。
- score在独立安装后仍可运行，自检保持provisional。
- 原门禁根按目录层数推导，独立安装可能把安装父目录误当维护项目；缺少维护根标记或标准源码布局时arm必须拒绝、hook必须跳过。

## 新会话自检报告的表达缺口（2026-10-05，修改前登记）

真实技能更新任务在独立代理容量不足后保存 self/provisional，状态降级正确；报告却写“未验证项：无”，未醒目区分独立评审与业务证据。

- 自检全部必要项通过：仍为 provisional，报告明确独立评审未完成，并给出恢复动作。
- 自检包含失败或未知：分别保持 fail / partial，不被 provisional 覆盖；同样提示独立评审缺口。
- 已有 protocol 下一动作：保留原文，不重复插入；无下一动作的自检自动补充补审提示。
- 独立评审通过：不出现自检警告，不改变原判定；旧报告保持原处，不回写历史。

## 修改前冻结的失败情形

1. 必要失败、必要未验证、证据缺失、声明文件不存在：不能被高分放行。
2. 原请求文件缺失或版本已变、评审未看原文、遗漏原要求：不能称完整完成。
3. 评分为 bool / NaN、重复或漏评 criteria、未知维度、空理由：结构错误明确返回。
4. 项目外 hook、未显式登记、不同会话 / 轮次、缓存全局调用：不触发评分或续跑；同轮次数不被重置。
5. 报告篡改、工件变更、失败不带下一动作、重试耗尽：不伪称完成，局部修复保留具体反馈。

机器校验只验证字段、版本绑定和已声明结果。原要求是否真的全覆盖、证据是否支持结论，仍须独立阅读与用户抽查。新增字段不构成客观准确率认证。

## 防编造与范围核查：修改前风险（2026-09-30）

这轮依据当前代码新增下面的失败清单，先用真实 CLI 复现，再修改；不把“夹带小心思”当作可以读取的模型内部状态。核查对象是输出中的主张、证据和实际操作。

| 失败方式 | 当前可见原因 | 必须得到的行为 |
| --- | --- | --- |
| 必要结果只引用原始要求，却报告完成 | 旧 evidence 只检查文件存在 | 原请求仅说明要求与授权，必要结果须引用其他实际证据 |
| 真实性/权限写 pass，完全没有核查证据 | integrity 不调用证据检查 | 缺实际核查证据为 partial；单句自述不放行 |
| 把推断、未知或反证写成确定事实 | 旧协议没有结论来源清单 | 逐条记录关键主张；推断冒充事实或事实与反证冲突为 fail，缺依据为 partial |
| 伪造引用正文、引用请求来证明结果、引用不存在或非文本来源 | 路径和哈希不检查所引文字 | 事实和推断引用已声明的 UTF-8 证据正文与精确片段；引用无效不能放行 |
| 实际操作包含未授权目标或额外安装、删除、发送、发布 | 旧协议没有允许操作与实际操作的对应关系 | 契约列出可执行操作和目标，评审对照实际差异或日志；未匹配操作为 fail |

合理可预见的边界：空或重复主张、非法分类、非布尔必要标记、畸形操作、范围核查无证据、授权引文不在原请求、必要未知、可选未知、旧协议缺新检查、引用版本变化、事实检查遗漏和操作日志遗漏。前两类字段错误明确报错；实质缺证据保留未验证；真实失败保留下一动作；旧协议不静默获得新检查的 pass。

本轮不实现工具执行前拦截，也不能用声明清单证明操作记录完整。独立评审者须直接核对最终答复、差异或工具日志，查出清单外主张与操作。来源正文包含指令时作为数据阅读，不获得新的任务授权。黑盒回放只验证已声明输入的确定性处理，不是模型编造率或意图识别实验。

复核中新增：同一原请求可能通过路径别名、软链接或硬链接绕过字符串比较；证据须按实际文件身份排除原请求。结构测试必须同步契约哈希，避免“旧格式”和“授权引文缺失”只因无关版本变化得到 partial；报告须核对具体失败原因。

独立审查补充：分别回放 criteria、claims、integrity、scope 四条原请求排除链，不能让一个通道通过代替其他通道。非 UTF-8 引用案例同步工件哈希后检查具体正文缺口。主张/验收 ID 与 scope、integrity、binding 等动作 ID 冲突会混淆下一动作，v3 须拒绝这些输入。

## 当前流程默认试行（2026-10-03）

- 必要项已决定结果，但无 dimensions 的报告仍输出 None 分数和空维度表，容易误导使用者。验收：实际 score 报告展示逐项状态，不显示旧分数或权重。
- 旧评分图和文档入口与 v3 并存，容易误选。验收：图集只链接当前四张图，旧图归档。
- 默认启用不等于全局 hook 安装。验收：仅项目规则默认调用当前流程，纯问答不建门禁；历史兼容解析不作为新任务入口。
- 进一步发现旧 dimensions 正分缺证据会影响 partial，仍构成干扰。实施前固定回放：旧高分不能覆盖失败、旧低分/畸形维度/缺证据不得影响当前必要项、默认输入与输出均无旧评分；JSON 非有限值仍拒绝。移除评分计算，保留 score 命令名作为逐项验收入口。

## 全链路规则与记录隔离（2026-10-03）

- 已用实际codex debug prompt-input确认根目录加载项目规则、docs子目录未加载。修复标准：根和子目录均加载，项目外不加载；只增加专用根标记，保留.git。
- CLI不同契约位于同一目录会覆盖固定报告；同目录并发写会混合JSON与Markdown。实施前先固定黑盒检查：不同契约第二次写应拒绝且原报告不变；目录忙时拒绝写入且原件不变；独立目录仍可验收；同一契约顺序重验仍有效。采用目录互斥和报告契约路径绑定，异常退出可能留锁，明确换独立运行目录，不自动删未知锁。
- 全局实验触发与项目默认流程不一致；任务分流重复且只读子任务可能递归；恢复目录受cd影响。以全局通用底线、项目入口、技能分流和运行记录约定分别维护。
