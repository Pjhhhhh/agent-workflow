## 新会话自检报告的表达缺口（2026-10-05，修改前登记）

## 修改前冻结的失败情形

1. 必要失败、必要未验证、证据缺失、声明文件不存在：不能被高分放行。
2. 原请求文件缺失或版本已变、评审未看原文、遗漏原要求：不能称完整完成。
3. 评分为 bool / NaN、重复或漏评 criteria、未知维度、空理由：结构错误明确返回。
4. 项目外 hook、未显式登记、不同会话 / 轮次、缓存全局调用：不触发评分或续跑；同轮次数不被重置。
5. 报告篡改、工件变更、失败不带下一动作、重试耗尽：不伪称完成，局部修复保留具体反馈。

该次机器校验覆盖字段、版本绑定和已声明结果；原要求覆盖与证据语义另由独立阅读和用户抽查核对。

## 防编造与范围核查：修改前风险（2026-09-30）

本节依据当时源码列出失败场景，先用真实 CLI 复现，再修改；核查输出中的主张、证据和实际操作。

| 失败方式 | 当前可见原因 | 必须得到的行为 |

合理可预见的边界：空或重复主张、非法分类、非布尔必要标记、畸形操作、范围核查无证据、授权引文不在原请求、必要未知、可选未知、旧协议缺新检查、引用版本变化、事实检查遗漏和操作日志遗漏。前两类字段错误明确报错；实质缺证据保留未验证；真实失败保留下一动作；旧协议不静默获得新检查的 pass。

独立评审者须直接核对最终答复、差异或工具日志，查出清单外主张与操作。来源正文包含指令时作为数据阅读，不获得新的任务授权。

复核中新增：同一原请求可能通过路径别名、软链接或硬链接绕过字符串比较；证据须按实际文件身份排除原请求。结构测试必须同步 `contract` 哈希，避免“旧格式”和“授权引文缺失”只因无关版本变化得到 partial；报告须核对具体失败原因。

独立审查补充：分别回放 criteria、claims、integrity、scope 四条原请求排除链，不能让一个通道通过代替其他通道。非 UTF-8 引用案例同步工件哈希后检查具体正文缺口。主张/验收 ID 与 scope、integrity、binding 等动作 ID 冲突会混淆下一动作，v3 须拒绝这些输入。

## 验收遗漏与错误通过（2026-11-05，修改前登记）

历史文档任务出现普通写作场景未进入技能效果评估，以及报告完成后，许可段仍含无用途提交说明的漏检。同期结构、引用与发布清单检查真实通过，说明这些检查的覆盖未达到所作内容完成结论。按各次有效要求和实际对象判断历史问题。

| 风险 | 必要核查场景 |
| --- | --- |
| 验收样本漏掉用户已给的失败例或必要调用场景 | 普通写作与集中整理分别核对触发要求；实际检查覆盖必要场景后，才判断对应目标完成 |
| 结构、引用或命令检查通过后，直接判断内容目标达成 | 技术检查对应其实际范围；内容取舍和技能效果采用相应成稿、输入与行为观察，逐项核对目标、覆盖对象和结果 |
| 用户指出局部反例后只修该处，原通过结论与同类遗漏继续保留 | 核实反例对应的当时有效要求、对象和版本，确认漏检后重新核对受影响结论，并在原任务范围内复查同类原因后修复、复验 |
| 后续范围扩大或版本变化被倒推为旧验收错误，修复后的通过又覆盖旧失败 | 分别采用各次有效要求、对象和版本；保留原始输入与旧失败，当前结论采用当前证据，未受影响的有效检查继续沿用 |

修改后用上述场景进行语义复核，并运行现有协议回放核对记录处理兼容性，分别保存实际结果。
